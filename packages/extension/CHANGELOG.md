# 変更履歴

## 0.2.2 - Project のアーカイブ

- Project 詳細の編集にアーカイブを追加した。
  保存すると PROJECT 一覧の行と期限マーカーだけを非表示にし、再起動後も維持する。
- EVENT 一覧、関連データと集計は維持し、再表示と復元の UI は設けない。

## 0.2.1 - 操作とタイムラインの改善

- Project名セルの右端ドラッグで列幅、下端ドラッグで全Project共通の行高を変更できるようにした。既定幅を280pxへ広げ、寸法スライダーを削除した。
- 寸法の上下左右キー、初期化と取消を用意し、既存の保存値を引き継いで同じVS Codeプロファイルの再表示と再起動でも保持する。
- タイムラインの日付を上端、必要ペースのグラフを下端に固定した。狭い領域でも固定部分と行操作の高さを確保する。
- 必要ペースの描画高さを約80%へ縮め、最大値を枠と背景なしの文字だけにした。両テーマの可読性を調整した。
- StoryとTaskをProjectと同じ専用ハンドルと上下キーで並べ替えできるようにした。Storyは同じEvent内、Taskは同じ所属内に限り、Taksは先頭固定とする。
- 並べ替えの保存失敗、取消と再操作で順序、選択と下書きを守り、キー操作後のフォーカスを維持する。
- READMEの操作説明と実VS Codeの画像を更新した。

0.2.0の管理ファイルはそのまま使用でき、今回の更新で保存形式と所属を変更しない。\
0.1.xからの更新には引き続き互換性と移行を提供しないため、以下の案内を確認する。

## 0.2.0 - 再設計版

### 0.1.x 利用者への重要な案内

0.2.0 は同じ拡張 ID `Glitch-Sound.glitchboard` の更新だが、旧管理ファイルの互換性と移行は提供しない。\
更新前に `manage.yaml` と参照する Project ファイル一式をバックアップする。\
旧データからの自動変換と自動削除は行わない。

1. 旧データを保管し、新しい空のフォルダを用意する。
2. VS Code の `glitchboard.manageFile` を未設定へ戻し、ユーザー設定とワークスペース設定に残る旧パスを解除する。
3. GlitchBoard の左の EVENT 一覧で `新しく作る` を使い、新しいフォルダへ管理ファイルを作る。
4. 保存先が新しい管理ファイルであることを確認し、Project と Event、Task を新しく登録する。

既存の設定先は更新後も参照されるため、旧データを読み込めた場合も互換性を保証するものではない。\
旧データをそのまま編集せず、新しい保存先へ切り替える。\
新規作成で既存の管理ファイルを上書きすることはできない。\
通常の編集と削除は、画面で操作した保存先のファイルへ反映される。

### 主な変更

- Event に Task を直接追加でき、Story の事前作成が不要となった。
- 直接 Task は正確に `Taks` と表示し、必要なときだけ任意の Story で整理する。
- 各レコードに詳細ボタンを設け、選択と詳細を分離し、表示中の詳細は選択へ追従する。
- 未保存の編集と追加下書きに保存、破棄、キャンセルの確認を設け、保存失敗時は入力を保持する。
- 左の Event 一覧、メインの構成、詳細、ポイントと日付の操作を統一した。
- Project の色をピッカーと16進数コードで指定できる。
- Project 列幅と共通の行高、上下の高さを調整できる。
- 期限切れの Event は左の一覧で管理する。
- 管理ファイルをユーザー設定へ保存し、yaml と yml の外部更新を監視する。
- 異なる Project に同じ UUID がある場合も、登録ファイルと ID の組で対象を特定する。
- ソースの管理先を [Glitch-Sound/glitchboard](https://github.com/Glitch-Sound/glitchboard) とした。

アイコン、publisher と拡張名は旧版を継続する。\
以前の公開版は0.1.5であり、本版はその更新として配布する。
