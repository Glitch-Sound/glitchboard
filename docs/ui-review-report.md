# カラーコードと画面レビューの結果

## 結果

Project の追加と詳細に16進数カラーコードの入力を追加した。\
保存形式に合わせて #RRGGBB の6桁を使い、大文字、小文字と前後空白を受け付け、小文字へ正規化する。\
短縮3桁、透過付き8桁、色名、空欄と不正文字は保存しない。\
既存のピッカー、コメント、UUID と直接 Task、任意 Story、Taks の構造を維持した。\
詳しい入力と取消の扱いは[カラーコードの報告](hex-color-report.md)に記録する。

その後に実ビルドを両テーマで操作し、キャプチャを観察して次を改善した。

| 見つかった問題 | 変更と根拠 |
| --- | --- |
| 左の Event 名と詳細ボタンが崩れていた | 旧 button.event-row の規則を現在の div と独立ボタンへ合わせた。幅240px、280pxで文字の領域、期限、詳細の重なりを実寸で確認した |
| 左の詳細だけ16pxの裸のアイコンだった | 共通の30pxボタンと枠を適用した。ファイル形のアイコンと補足の有無による色、独立した1回の選択と詳細の動作を維持した |
| 月の詳細ボタンが ◆ に重なった | 月だけ補助詳細をホバーとキーボードフォーカス時に上へ表示する。マーカーと補助ボタンまでポインターを移せ、1クリック、Tab と Enter で開けることを確認した |
| 空の一覧が理由も入口も示さなかった | Project 未登録、全非読込、Event 不在と抽出結果なしを区別し、左右で既存の追加と抽出の入口を案内する |
| エラーが通常の本文に埋もれた | 左右で警告アイコン、枠と背景を共通化し、原文と role=alert を維持した。長いパスも折り返す |
| 淡色や黒の Project 名を読みにくかった | 設定色の枠をそのまま保ち、タイトル文字をテーマ前景へ寄せた。保存色とマーカーは自動変更しない |
| 抽出条件の終了方法と背景が不統一だった | Escape と枠外で閉じ、Escape は入口へ戻す。検証環境で menu 用変数がないと背景が透明になったため、editor と panel へのフォールバックを加えた |
| 同時保存後も色が未保存になった | 名前や補足と保存した色も成功時にコード欄へ確定する。失敗時の入力は維持する |

新しい操作ボタンを増やして入口を重複させず、既存の階層、選択と詳細の区別を維持した。\
月の補助詳細は通常時に隠れるが、左の一覧と下部の Event 要約の詳細ボタンは常時表示のままである。

## 実際に確認した範囲

Mac の一時 YAML と実 BoardSession、実ビルドの React 画面を Chromium で操作した。\
VS Code API と通信をアダプターへ置き換え、ダークとライトのテーマ変数を与えた。\
メインは1440x900、左は幅240pxと280px、Project 列は最小幅も確認した。\
UI レビュー用だけで28状態を両テーマ、計56枚に記録し、一覧、各階層詳細、追加と編集、カレンダー、ポイント、削除確認、空状態とエラーなどの代表画像を実際に観察した。

| 領域 | 実操作と確認 |
| --- | --- |
| 初期設定 | 未設定、不在、選択と作成の入口、キーボード操作、取消、案内が左だけに出ること |
| 一覧 | 期限切れ、今後、抽出、名前と余白の選択、詳細、全 Project の読み込み解除と復帰 |
| メイン | 3日、1週間、月、行高と列幅、再表示、スクロール、ドラッグとキーによる調整と並べ替え |
| 詳細 | Project、Event、Story、Task の所属表示、補足、名前、期限、色、ポイントと削除の取消 |
| 色 | 実追加、コードとピッカーの同期、実保存と再読込、無効値、色だけの取消、失敗後の再試行、名前と補足との同時保存 |
| 入力保護 | 詳細の未保存確認、追加下書き、取消、保存失敗、再接続と同じ UUID を持つ別 Project の対象保全 |
| 空状態とエラー | 未登録、全非読込、Event 不在、抽出結果なし、不正 YAML、長いパス、保存失敗と復帰 |

画面の描画検査では、左の名前領域が幅240pxで約108px、280pxで約148pxとなり、詳細は30x30pxで重ならないことを確認した。\
白、黒、淡色の詳細タイトルを両テーマで測り、今回の背景とのコントラストは最小約4.95だった。\
この数値は対象の検証色とテーマの結果であり、すべてのカスタムテーマへの適合認証ではない。\
ボタンの入れ子、名前のないボタン、ページ全体の横はみ出しとブラウザーの実行エラーは検出されなかった。

## テストと検査

カラーコードの最初の7件、入力途中のプレビュー、空状態とエラーの5件、抽出条件の終了、同時保存の確定表示を、対策前の失敗で確認した。\
実ブラウザーでも、左の崩れ、共通ボタンの大きさ、暗色タイトルのコントラスト、抽出背景の透明化と月の重なりを修正前に再現した。\
単に存在する文字を探す検査にせず、パッチ全体、コードの完全一致、保存された YAML、クリック要求の件数、描画した寸法と色を照合した。\
既存のテストの期待値を弱めたり、検査を無効にしたりしていない。

最終の npm run check は、106ファイルの296テスト、lint、型検査、FSD、ビルド、7 capability の厳格検証とトレースを成功した。\
npm run test:ui の7本も成功し、カレンダーの12組合せ、初期設定の8組合せ、両テーマの反復操作、寸法と期間表示を含めて回帰確認した。\
[最終の検査結果](../artifacts/ui-review/check-results.json)、[全体検査ログ](../artifacts/ui-review/check.log)、[画面検査ログ](../artifacts/ui-review/all-ui.log)に結果を記録する。

通常の check と check:product は変更していない。\
test:ui は従来の2本に再接続、初期設定、今回の画面と色、レイアウト、カレンダーの5本を追加した。\
OpenSpec の trace.json でも実際に実行する verify スクリプトをテスト参照へ含め、参照検査と実行の結果を区別している。

OpenSpec の[設計](../openspec/changes/archive/2026-11-14-refine-reviewed-ui/design.md)と[検証](../openspec/changes/archive/2026-11-14-refine-reviewed-ui/verification.md)を正式仕様へ同期し、アーカイブした。

## 最終確認と未確認事項

最終の VS Code 実操作は利用者が行う。\
ブラウザーで実アプリを動かしたが、VS Code 本体のメニュー、ネイティブ色ダイアログとファイルダイアログ、ユーザー固有のプロファイルやカスタムテーマを実機操作した結果ではない。\
[手動確認](../openspec/manual-checks.md)には今回7行を追加し、既存項目の未確認状態は維持している。

1. Project の追加と詳細で #RRGGBB を入力し、ピッカーとの一致、保存、再表示と再読込を試す。
2. 無効値、色だけの取消と Escape、名前や補足との同時保存、失敗後の再試行と移動のキャンセルを試す。
3. 左の名前、行の余白と詳細が独立し、狭いペインでも読めることを確認する。
4. 抽出条件の Escape と枠外操作、Project 全非読込と復帰、0件の案内を確認する。
5. 白、黒、淡色の所属表示と、長い失敗理由が両テーマで読めることを確認する。
6. 月の ◆ にホバーまたはフォーカスを移し、補助詳細を1クリック、Tab と Enter で開く。

未解決の実装上の指摘はない。\
push、Marketplace 公開、README への画面キャプチャ追加は行っていない。
