# 実機確認後の操作改善

最新の起動と設定案内の集約は [起動改善報告](startup-guidance-report.md) を参照する。

最新の追加下書きの保護は [修正報告](inline-draft-fix-report.md) を参照する。

## 結果

メニューから左右両画面を開き、レコードの選択と詳細を分けて統一した。\
詳細が開いていれば選択先へ追従し、編集中は保存、破棄、キャンセルで入力を守る。\
左ペインからの操作も、選択を確定する前に同じ確認を通す。

## 変更と根拠

| 要望 | 実装した動作 |
| --- | --- |
| メニューからの起動 | サイドバーの解決時と再表示時にメインパネルを開き、既存タブがあれば再利用する |
| 左ペインの詳細 | 共通の書類ボタンで、所属 Project の参照を保って対象 Event の詳細を開く |
| 上部の操作 | Event 追加を左の EVENT 一覧へ集め、ボードの空状態もその入口を案内する |
| 寸法 | 列幅と全 Project 共通の行高をスライダーとキーで調整し、Webview 状態で再表示後も維持する |
| 期限切れ | タイムラインの専用列とマーカーを除き、EVENT 一覧から操作する。残作業とペースなどの計算には引き続き含める |
| Story と Task | 見出しを Story、直接 Task の仮想グループ名を正確に Taks とし、チェックと名前の間隔を広げる |
| 詳細の所属 | 全種類で Project 名と設定色をタイトルにし、その下へ対象種別と名前、階層を表示する |
| ポイント | 一覧と詳細が同じバッジ、スライダー、数値、未見積の部品と色を使う |
| レコード選択 | Project はその Event、Event は Story、Story は Task の情報を示す。名前だけで詳細を開く旧操作をやめる |
| 編集中の移動 | 元の対象への保存成功後か明示的な破棄後だけ進み、キャンセルと失敗では対象と入力を保つ |

「自動作成される Story」に該当する保存レコードは現行モデルに存在しない。\
該当する表示は Event.tasks をまとめる仮想グループであり、その名前を利用者指定どおり Taks とした。\
Story を自動保存する仕組みは追加せず、UUID、Project YAML の構造、コメントを維持する。\
Taks 自体には独立した保存属性や編集対象がないため、実 Story と異なり固有の詳細は作らない。

初期の列幅は240px、行高は従来の44pxから56pxとした。\
列幅は180〜480px、行高は44〜120pxで調整し、画面縮小時は日付領域を残す上限へ収める。\
値の正本は widgets/timeline/model/dimensions.ts であり、描画検査も同じ定義を参照する。\
Home とダブルクリックは初期値へ戻し、調整中の Esc と Pointer Cancel は開始値へ戻す。\
再表示時に状態が無効であっても初期値と上限で保護する。

選択ボタンと独立操作ボタンを兄弟にして、入れ子とイベントの二重発火を避けた。\
左ペインの移動要求は共有スキーマで検証してボードへ渡し、準備前は最新の要求を保留して ready 後に届ける。\
保存中の二重送信、確認中の追加要求による移動先の上書き、保存失敗による下書き消失を防ぐ。

## 検証

最終状態の全体検査は97ファイル、216テストである。\
lint、型検査、FSD、全テスト、ビルド、7 capability の厳格仕様とトレースを確認する。\
結果とログは artifacts/interaction-refinement/ に記録する。

| 検証 | 根拠 |
| --- | --- |
| 修正前の失敗 | 新規操作5件、寸法1件、メニュー起動1件を旧実装で失敗させた |
| 配色の回帰 | 計算済み CSS 色の一覧と詳細の不一致を検出してから古い上書きを除いた |
| 小画面の回帰 | 実描画の縮小で列幅上限が変わらない失敗を検出し、上下の暗黙の最小幅を分離して到達性を保った |
| 取消の回帰 | Pointer Cancel が寸法を戻さない失敗を検出してから修正した |
| 空の Project | 選択した Project に Event がないとき、他 Project の下位情報を残さない回帰を確認した |
| 編集の分岐 | 名前、補足、期限、保存成功と失敗、不正日付、破棄、キャンセル、二重送信と追加移動を確認した |
| 実保存の反復 | 両テーマで追加と取消、実 EACCES と再送、ポイント、補足、完了と解除、子件数、削除を確認した |
| 左右の接続 | 同じ UUID の2ファイルで左から選択と詳細を切り替え、取消と破棄、保存対象と対象外ファイルの非変更を確認した |
| 寸法と再表示 | 全行への同じ高さの適用、最大値、小画面への縮小、キー操作、状態の再表示を確認した |
| 既存操作 | カレンダー12組合せ、初期案内8組合せ、両テーマの上下調整と並べ替えを回帰確認した |

既存テストの期待値は、依頼により変更した名前の直接詳細、上部追加、期限切れ列、固定行高と Esc の確認を新しい振る舞いへ更新した。\
副作用の対象、保存内容、失敗時の保持、独立操作の検査は維持した。\
カレンダー回帰では、空の期限で選択画面を開く既存動作も補修し、再検証した。

## 利用者による最終操作確認

[manual-checks.md](../openspec/manual-checks.md) の隔離起動で、新しい管理ファイルを使う。\
実 VS Code の最終 GUI 確認は利用者が行う。\
今回の要点は次の順で確認する。

1. メインタブを閉じて別のサイドバーへ移り、GlitchBoard を選び直して左右両画面が開くことを確認する。
2. Project、Event、Story、Task と左の Event の名前、余白、書類ボタンを順に操作し、選択と詳細の違いと追従を確認する。
3. 詳細で名前、期限、補足を編集中に別レコードへ移り、保存、破棄、キャンセルと失敗後の再送を試す。
4. 列幅と行高を両端まで調整し、画面縮小と再表示、Esc、Home、ダブルクリックを試す。
5. 期限切れを左から開き、Taks と任意 Story の Task、詳細の Project 色、両面のポイント操作を確認する。
