# Project 色のコード入力

Project の追加と詳細に、ピッカーと同期するカラーコード欄を加えた。\
#RRGGBB の6桁、大文字、小文字と前後空白を受け付け、保存時は小文字へ正規化する。\
短縮3桁、透過付き8桁、色名、空欄と不正文字は保存せず理由を示す。\
YAML の保存形式を広げず、コメントと UUID を維持する。

詳細の直接入力は「色を保存」または Enter で確定し、「色を取消」またはコード欄の Escape で保存済み値へ戻る。\
色だけの操作で名前と補足の編集を消さず、移動確認では変更した項目をまとめて保存する。\
保存失敗、無効値と移動のキャンセルでは未保存内容を保つ。\
既存の詳細ピッカーの即時保存は維持する。

最初に追加した入口と詳細の7テストは修正前にすべて失敗した。\
無効な入力途中のプレビューも、追加テストの失敗を確認して修正した。\
形式の境界では、以前からの保存スキーマが受け付ける6桁の範囲を共通の定義へ移し、保存用には空白許容を持ち込まないことを確認した。\
最終の色対応時点で104ファイル、289テストと lint、型検査、FSD、ビルド、仕様とトレースが成功した。

実ビルドと実 BoardSession、一時 YAML を用いるブラウザー検証では、両テーマで追加、詳細の保存、再読込、ピッカー表示と左の色の一致、無効値、取消、失敗後の再試行、名前との同時保存を確認した。\
狭い Project 列でも色入力が窮屈にならないよう、名前、色と確定操作を縦へ配置した。\
VS Code API と通信はアダプターであり、実 VS Code のネイティブ色ダイアログはユーザーの最終確認に残す。

初期の色対応の検査には CSS 詳細度の警告が1件あり、後続の画面レビューで解消した。\
現在の最終検査は [画面レビューの報告](ui-review-report.md)を参照する。

実画面の観察で見つかった EVENT 行、空状態、エラー表示と淡色タイトルの改善は、別の UI レビューで扱う。\
対応形式と色の操作は [manual-checks.md](../openspec/manual-checks.md) の REQ-042-S06 で最終確認する。\
