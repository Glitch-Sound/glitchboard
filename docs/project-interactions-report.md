# Project操作と固定表示、並べ替えの検証

## 変更内容と判断

依頼順に、セル端の寸法操作、日付固定、StoryとTaskの並べ替え、必要ペースの固定を実装し、それぞれの検証後に次へ進めた。

| 改修 | 結果 | 主な検証 |
| --- | --- | --- |
| Projectセル端 | 右端で列幅、下端で全Project共通の行高を変更する。既定幅280pxを保持し、スライダーを削除した | 境界、後続行の追従、取消、捕捉喪失、キー、狭幅、入力保持、再表示と再起動 |
| 日付固定 | 日付とProject見出しを上端へ固定し、同じ表の横位置を維持する | 16件、1件、0件、320px幅の実横スクロール、期間と寸法、フォーカス |
| StoryとTaskの順序 | Projectと同じハンドル、前後の挿入線、上下キーを使い、保存後に反映する | 両方向、両所属、取消、自己と外部、境界、保存失敗、再読込、下書きと詳細編集 |
| 必要ペース固定 | 同じ表のフッターを下端へ固定し、日付とグラフの横位置を揃える | 先頭、途中、末尾、最大値ラベル、実績線、最小領域、両テーマと詳細操作 |

列幅は180〜480px、行高は44〜120px、既定行高は56pxを維持した。\
右端は左右キー、下端は上下キー、Homeとダブルクリックは対象寸法の初期化、Escは調整前へ戻す操作である。\
後続行の下端では、その行までの件数で移動量を割り、つかんだ境界をポインターへ追従させる。\
既存のWebview保存寸法を引き継ぎ、同じVS Codeプロファイルへ順次保存する。\
画面の縮小は表示だけに適用し、保存幅とYAMLを変更しない。

Storyは同じEventの配列、Taskは同じEvent直下または同じStoryの配列だけを移動する。\
Taksは先頭固定の仮想行であり、その中の直接Taskは並べ替えできる。\
所属を変える操作は追加していない。\
Projectファイルと親、移動元と移動先を最新データへ照合し、別Projectの同じUUIDや表示後に所属が変わった要求で他のデータを更新しない。\
YAMLノードを移動し、ID、補足、コメント、完了状態と集計を保持する。

上下の固定部分と行の操作領域を実測して最小高さへ反映する。\
極端に小さい画面では、固定部分を重ねずにボード全体をスクロールできるようにした。\
通常の初期比率3対2と、下部80pxの下限は維持する。

## 検査結果

| 検査 | 結果 |
| --- | --- |
| npm run check | 116ファイル336テスト、lint、型検査、FSD、ビルド、正式仕様と追跡、文書検査に成功した |
| npm run test:ui | 既存9本と追加2本の全11検査に成功した |
| npm run test:ui:native-cells | 実VS Code 1.146.0、両テーマでドラッグ、タブ再表示、拡張再起動、上下固定と最小領域の詳細操作に成功した |
| npm run test:ui:native-reorder | 同じ実VS Code、両テーマでStory、直接Task、Story内Taskの実ドラッグ、保存、取消、キー、フォーカスと再表示に成功した |
| README表示と一時VSIX | 5画像の実表示、共通倍率、画像とREADME、サンプルの同梱とバイト一致を確認した |

追加の境界、保存要求、並べ替え、固定グラフと最小高さは、実装前にテストの失敗を確認した。\
日付固定は最初の実行がテストデータのUUID形式で止まったため、データ修正後に固定を無効にした負例で失敗を確認した。\
実画面で見つかったキー移動後のフォーカス復元は、実VS Codeで失敗と修正後の成功を確認した。\
jsdomは無効ボタンのフォーカス制約を再現せず、その期待値は修正前も成功した。\
従来の極小画面での上下比率の期待値だけは、固定部分を含む新しい最小高さと操作可能性の検査へ変更し、その他の既存検査を維持した。

全体検査のプロダクト側の集約コマンドcheck:productは変更していない。\
test:uiには並べ替えと上下固定の2検査を加え、任意の実VS Code検査としてtest:ui:native-cellsとtest:ui:native-reorderを追加した。

## 最終操作確認

1. 開発ホストでサンプルのmanage.yamlを設定し、Project名セルの右端と下端をドラッグする。
2. 境界の左右または上下キー、Home、ダブルクリックとEscを試し、タブの開き直しとウィンドウ再読込でも寸法を確認する。
3. Projectを複数表示して縦にスクロールし、日付と必要ペースが上下に留まることを確認する。狭幅と上下境界の最小位置でも詳細へ移動する。
4. StoryとTaskのハンドルを前後へ移し、上下キーとEscも試す。Taksが先頭固定で、所属を変えずに順序だけ保存することを確認する。
5. 追加と詳細編集の下書きを作って並べ替え、選択を変える確認でキャンセルし、入力が残ることを両テーマで確認する。
