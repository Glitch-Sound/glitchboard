# Project アーカイブの実装と検証

## 変更と保存

Project 詳細の「編集」で「アーカイブ」をチェックし、「保存」で確定する。\
保存した Project YAML に任意の真偽値 archived を追加し、true の Project は PROJECT 一覧の行と期限マーカーだけを非表示にする。\
省略と false の Project はこれまでどおり表示し、既存ファイルの読込では属性を補わない。\
関連する Event、Story、Task、補足、コメント、未知の属性、UUID と登録ファイルを保持する。

アーカイブは load 設定と独立する。\
EVENT 一覧、Event の選択と詳細、未保存の追加入力、必要ペース、実績と危険判定を含む読み込み対象の集計は維持する。\
全 Project をアーカイブしても日付、必要ペース、Project 追加と左からの Event 操作を残す。\
再表示と復元の UI は追加せず、編集中の説明にもその点を明記した。

## 検証

- 新規テストを先に実行し、保存スキーマと通信の未対応で2件、編集欄と一覧除外の未対応で8件の失敗を確認した。
- 読込時の非変更と禁止要求の拒否は既存の保存境界が満たしており、最初から成功した。
- 新規12テストで真偽値の検証、読込時の非変更、別ファイルの同一 UUID、コメントと子の保持、セッション再生成、取消、移動の保存、破棄とキャンセル、保存失敗と再試行、表示行同士の並べ替えを確認した。
- 全件アーカイブの画面テストでは PROJECT 行とマーカーの集合を0件と照合し、EVENT 名の全件一致、選択要約、ヘッダーの集計と追加下書きの保持を確認した。
- 実 VS Code 1.146.0 を隔離プロファイルで起動し、Default Dark Modern と Default Light Modern の両テーマで保存、タブの再表示、拡張の再起動と全件アーカイブ後の EVENT 詳細、Task 完了の接続を確認した。
- 実画面のチェックは Space で切り替えられ、2px のフォーカス枠を持つ。
  両テーマの4画像を開き、説明文、フォーカス、保存操作と非表示後の画面を目視した。
- 実データを開かず、一時ディレクトリの2件のサンプルだけを操作した。
  他 Project と manage.yaml のバイト列が不変であることを保存前後に照合した。

実画面と結果は `artifacts/project-archive/`、再実行は `npm run test:ui:native-archive` を使う。\
通常の check と check:product の検査内容は変更せず、実 VS Code の専用検査コマンドだけを追加した。

全体検証の npm run check は119ファイル348テスト、lint、型検査、FSD、ビルド、7仕様の strict 検査、トレースと文書同期を含めて成功した。\
npm run test:ui は既存の11検査すべてに成功した。\
今回の実画面と結果は artifacts/project-archive の4画像と native-results.json に記録した。\
既存の利用者プロファイルの手動確認台帳には39件の未確認情報が残るが、今回の自動検査の失敗を意味しない。

## 最終操作確認

1. サンプルを読み込み、PROJECT 行の詳細ボタンから「編集」を開く。
2. 「アーカイブ」をチェックして「取消」を選び、行が残り、再編集で未チェックになることを確認する。
3. 再びチェックし、別レコードへの移動確認をキャンセルして入力が残ることを確認する。
4. 「保存」で行とマーカーが消え、左の EVENT と Task、必要ペースが維持されることを確認する。
5. タブの開き直しと VS Code の再起動後も Project 行が非表示で、左の EVENT から操作できることを確認する。

## 制限

復元 UI と集計からの除外は今回の対象外である。\
README の既存5画像はアーカイブの編集欄を写しておらず、引き続き説明と一致するため撮り直していない。\
実装完了時点では push、コミット、Marketplace 公開は行わず、追加の公開依頼に基づく配信は [0.2.2の配信記録](release-0.2.2.md)で管理する。\
通常の利用者プロファイルでの最終操作確認は利用者が行う。
