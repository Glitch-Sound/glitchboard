# 選択背景と枠の整理

## 変更内容と根拠

最新の指定を優先し、以前の Story 表現の維持という方針を更新した。\
Event と Task は既存の選択背景を維持して選択枠をなくし、Story は背景を変えず選択枠も出さない。\
Project の左線、詳細ボタンの選択前景、危険色と完了の取り消し線は維持した。

変更は style.css の Story と Event の selected、Task の focus-within に限定した。\
Task の行にある focus-within の outline はマウス選択後にも残るため取り除き、ボタンと余白の record-hitbox の focus-visible は残した。\
キーボードで余白ボタンを操作した場合は行を囲うフォーカス枠が出るが、選択だけで表示する枠とは区別する。\
選択と詳細、未保存の確認、保存モデル、共有スキーマ、通信、YAML と ID を変更していない。

正式仕様の REQ-030 と REQ-035、product.md と tech.md、未確認の実機台帳を更新した。\
新しいプロダクト検査や依存関係は追加せず、既存の test:ui に含まれる検査を更新した。

## テストと誤りの検出

最初にブラウザー検査の期待値を新しい指定へ変更し、実装変更前の両テーマで16件の失敗を確認した。\
通常 Story と Taks の背景、Story と Event の4表示箇所、Task の行枠で失敗しており、変更前の振る舞いを見逃していない。\
変更前の背景の値を基準として残し、実装後に Event の4表示箇所と Task の背景が完全一致することを確認した。\
Story の詳細ボタンの選択前景も変更前と一致する。

フォーカス枠の既存の期待値は、outline の文字列の先頭だけでは無効な表示を見逃す可能性があったため、outline-style が none でなく幅が正であることへ強めた。\
一時ファイルの検査だけに focus-visible の枠を無効にする CSS を与え、両テーマで16件のフォーカス失敗を検出した。\
本体の CSS を弱めたり、検査を無効にしたりしていない。

| 確認 | 結果 |
| --- | --- |
| 選択、未選択、ホバー、名前と余白のフォーカス | 両テーマで成功 |
| 左の Event、マーカー、同日一覧、要約 | 背景を維持し、選択枠なし、選択詳細を強調 |
| 通常 Story と Taks | 背景と選択枠なし、通常 Story の選択詳細を強調 |
| 通常と完了の Task | 背景を維持し、選択枠なし、完了線とポイントを維持 |
| 詳細の切替と独立操作 | 詳細ボタン、完了、ポイントが二重発火しない |
| 編集の確認 | 保存、破棄、キャンセルと保存失敗、選択確定の回帰が成功 |
| 既存の UI 検査9本 | 両テーマ、反復操作、再接続、レイアウト、日付入力を含め成功 |
| 全体検査 | lint、型検査、FSD、107ファイル298テスト、ビルド、仕様7件、トレースと文書検査が成功 |

REQ-030-S01 は既存の部品テストが同じ予測日、進捗と設定色を検査していたため、期待値を変えずシナリオ ID のコメントを補った。\
この部分は製品を変えておらず、最初から成功する既存動作である。\
変わった表示は実ビルドのブラウザー検査、計算済みの予測と進捗は既存の部品テストで確かめ、判断を別の層に複写していない。

変更前、変更後の結果と画像、失敗ログ、フォーカスの負例は artifacts/selection-surfaces に残した。\
変更後は両テーマ合計38画像を記録し、選択だけの状態とキーボードフォーカス中の状態を分けて表示確認した。

UI 検査9本の成功後、フォーカスを外した選択状態と進捗位置を含む選択検査も最終ソースで再実行して成功した。\
テストを広げた部分の結果は selection.log に残した。
