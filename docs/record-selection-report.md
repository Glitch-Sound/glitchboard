# レコードの選択表現の報告

## 変更内容

Story の選択操作と見た目を基準に、選択先と詳細ボタンの関係を揃えた。

| 対象 | 変更 |
| --- | --- |
| Project | 名前のホバー下線を外し、名前セルの余白もポインターにした。設定色の選択左線を保ち、左線と同じ条件で詳細ボタンを強調する |
| Event | 左の一覧、タイムラインのマーカー、同日一覧の対象行、下部の表示中の要約を選択表示にした。選択中の詳細ボタンを強調する |
| Story | 操作と表示を変更していない。選択、未選択、ホバー、フォーカスの算出スタイルを修正前後で完全一致比較した |
| Task | 名前のホバー下線を外し、選択中の詳細ボタンを強調した。完了の取り消し線、ポイントと完了の操作を維持する |

詳細ボタンは選択中だけ Story と同じテーマの選択前景を使う。\
ライトでは白に固定せず濃い前景で強調し、未選択では補足ありの青と補足なしの灰色へ戻る。\
Event の危険な名前と期限の赤、Project の設定色、完了の表示を維持している。

画像の確認で Project 名のフォーカス枠が省略表示の領域で欠けることを見つけ、セル内側にもキーボードのフォーカス枠を追加した。\
長い名前でもフォーカス位置を判別できる。

## 選択状態と入力保護

左の一覧へ既存の scopedEventSelection を渡し、Project ファイルの参照を含む選択を使う。\
クリック直後の局所状態で先に色を変えず、既存の未保存確認を通ってから左右の表示を更新する。\
別 Project の同じ UUID でも選択対象を混同しない。

レコード全体と名前、独立した詳細の既存の操作経路を維持し、通信、YAML、ID、計算と入力保護の判断は変更していない。\
編集中の移動確認、キャンセル、保存失敗では元の選択と入力を保ち、保存成功と明示的な破棄で選択を確定する。\
Story と直接 Task の Taks の意味も変更していない。

## 空の Project の追加検証

最後の境界確認で、空の Project を選んだときに左の以前の Event が選択表示のまま残ることを再現した。\
既存のセッションの選択解除を null のメッセージから呼び、左右へ反映する。\
解除の応答と同じ snapshot を再表示した後も、空 Project の設定色の左線と詳細の強調を維持する。\
編集中の移動をキャンセルした場合は解除を送らず、元の入力と選択を維持する。

共有境界と実セッションの新しい2テスト、既存の Extension の接続検査への追加確認を、修正前の3件の失敗で確認した。\
実画面でも左右の不一致2件と、応答後の Project 選択が消える4件を検出してから修正した。\
検査ではセッションの解除と再表示後の描画完了を待ち、一瞬だけ正しい表示を成功と誤認しないようにした。\
反復した解除でも管理ファイルと Project ファイルのバイト列を変更しないことを実セッションで確認した。

## 最終確認と未確認事項

1. 両テーマで Project 名と余白をホバーし、下線とカーソル、クリック後の設定色の左線と詳細の強調を確認する。
2. Tab、Shift+Tab と Enter で長い Project 名、Event と Task を選択し、フォーカス位置を判別できることを確認する。
3. 左の Event、タイムラインと同日一覧、下部の要約で選択と詳細の強調が一致し、危険色が残ることを確認する。
4. Task の通常と完了、ポイントと詳細を操作し、Story の操作と表示が以前と同じことを確認する。
5. 詳細編集中の別レコードへの移動で保存、破棄、キャンセルを試し、キャンセル時の入力と元の選択表示を確認する。
6. 空の Project を選択し、左右の Event 選択が解除され、Project 自体の左線と詳細の強調が応答後も残ることを確認する。

VS Code 本体の利用者のプロファイル、任意のカスタムテーマと最終実操作は未確認である。\
