# 必要ペースの高さと数値表示の調整

## 変更内容

描画部分の高さを58pxから46px(約79%)へ変更した。\
文字サイズと上余白を保持するため、固定領域全体の実測は69pxから57px(約83%)となった。\
SVGは親の高さへ追従し、座標系、計算と日付列の横位置は変えない。

最大値はpt付きの文字だけにし、枠、背景の塗りと内側余白を除いた。\
超過時はチャートの赤25%とテーマ前景75%を混ぜ、箱がなくても数値を読めるようにした。\
通常はテーマ前景を使い、文字と最大値のグラフ線の間隔は約5pxを保つ。

前回の4改修のTypeScript71ファイルは変更前後のハッシュがすべて一致した。\
列幅280px、セル端の操作、上下固定、StoryとTaskの並べ替え、寸法保存と編集保護を維持した。

## OpenSpecの扱い

高さは正式仕様に数値を定めていないため、AGENTS.mdの値の調整として直接変更した。\
高さの定義をCSSの1か所へまとめ、既存テストの期待値を変更せずに検証した。\
枠と背景はREQ-017の本文に定義されていたため、simplify-pace-labelのff、apply、verify、archiveで文字のみの表示へ変更した。\
REQ-017-S03に両テーマ、狭幅とホバーを追加し、既存の学習中と超過のシナリオを維持した。

## 検査結果

- npm run check: 116ファイル336テスト、lint、型検査、FSD、ビルド、OpenSpecと文書検査が成功した。
- npm run test:ui: 最終表示で全11検査が成功した。
- npm run test:ui:native-cells: 実VS Code 1.146.0の両テーマで上下固定、サイズ変更、最小領域の詳細操作、再表示と再起動、YAMLの不変を確認した。
- ラベルの枠0px、背景の透明、影の不存在、最大値の線より上の位置、SVGと親の高さの一致を実Chromiumで確認した。
- 検証用テーマのコントラストは超過でダーク約9.54:1、ライト約9.45:1、通常で約11.98:1と約12.63:1となった。
- 320px幅、280px高を含む最小領域、先頭、途中、末尾のスクロールとホバーを検証した。

背景を除く前の検査は、背景のalpha255に対する期待値0で失敗した。\
ホバーで透明になる負例も検査し、opacityの完全一致を加えて誤った可視判定を防いだ。\
既存のホバー動作は最初から成功し、新たな動作を加えていない。
