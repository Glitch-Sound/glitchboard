# 再設定時の下書き保護

## 結果と原因

管理設定を解除し、同じ manage.yaml を左から選び直しても、非既定 Event と Story の選択、Task 追加と詳細編集の入力を保つ。\
原因は configure が毎回新しい BoardSession を作り、初期 Event の選択で EventDetails が再マウントされることだった。\
設定解除後も最後のセッションを保持し、同じ正規化済み絶対パスなら再利用して再読込する。

## 別の管理ファイルへの変更

別ファイルへの変更は、詳細編集、Event 内の追加入力、Project の追加入力の順に保存、破棄、キャンセルを確認する。\
左からの選択と作成は確認後に設定とファイルを変更し、設定画面からの変更をキャンセルした場合は元の設定へ戻す。\
確認するメインを表示し、確認中は元の選択を保つ。\
設定解除中の通常保存は拒否し、確認で明示的に選んだ保存だけ元のセッションへ配送する。\
保存失敗では確認と未保存内容を残し、再試行またはキャンセルを選べる。\
保存と破棄を完了した入力は、後続の確認の取消によって未保存状態へ戻さない。

操作と左からの移動には表示時の管理ファイルの識別子も付ける。\
同じ Project 相対参照と UUID の別データへ切り替えても元の選択と入力を引き継がず、遅れて届いた古い接続の操作は拒否する。\
設定変更は直列化し、古いファイルの遅い読込完了は新しい設定の判定を妨げない。

承認から接続処理の完了までは元の表示への新しい入力を止める。\
切替先が欠落する場合も前の表示を残すが、以前の接続であることを示して読取専用にする。\
これにより、切替先の復元で新しく入力した下書きが消えることを防ぐ。\
切替先を復元すると新データで操作可能に戻り、設定保存や新規作成が失敗した場合も一時的な入力停止を解除する。\
同じ接続の欠落と設定解除では従来どおり下書きを保持する。

## 影響と境界

変更はセッション寿命、共有メッセージ、左右の操作要求、詳細と追加欄の移動確認に限る。\
YAML の形式、コメント、UUID と計算は変更せず、旧版の互換性と移行も追加していない。\
同じファイルの判定は絶対パスの字句的な正規化で行い、別シンボリックリンク名では安全側に変更確認を行う。\
下書きと最後のセッションは拡張の終了を越えて保存しない。

## 最終操作確認

[実機確認](../openspec/manual-checks.md)の隔離したプロファイルとコピーした検証データを使う。

1. 2件以上の Event と複数 Story を用意し、既定以外の Event の2番目の Story へ Task の追加下書きを入力する。
2. 選択中の Story の詳細も編集し、管理設定を解除して、左から同じ manage.yaml を2回選び直す。
3. Event と Story、両方の下書きが残り、追加時は元の Story にだけ1件保存されることを確認する。
4. 別ファイルを選んで詳細確認をキャンセルし、Task の追加下書きも残ることを確認する。
5. 保存と破棄で別ファイルへ進み、元ファイルへの保存と、新しいファイルに混ざらないことを確認する。
6. 元の検証用管理ファイルを一時退避して保存を失敗させ、入力と確認が残ること、復元後の再試行とキャンセルができることを確認する。
7. 設定画面からの別ファイル指定をキャンセルして元へ戻ること、Project 追加の名前と色も同様に保護されることを確認する。
8. 別の欠落した設定先へ変更した場合は前の表示が読取専用となり、復元後に新データを操作できることを確認する。
