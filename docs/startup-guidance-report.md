# 起動と設定案内の集約

## 変更

メニューからの起動は最新の設定判定を待ち、案内の入口を左の EVENT 一覧へ集めた。

| 状態 | メニューとコマンドの結果 |
| --- | --- |
| 設定済みで管理ファイルが存在する | EVENT 一覧とメインを開き、設定案内を表示しない |
| 未設定 | EVENT 一覧だけを開き、選択と新規作成を案内する |
| 設定済みファイルの欠落 | EVENT 一覧だけに理由とパス、選択と新規作成を表示し、新しいメインを作らない |
| 構文不正、権限エラー、Project の欠落 | 設定済みのエラーとして両画面で理由を示し、設定案内へ誤分類しない |
| 初回判定中または設定切替中 | 判定前に新しいメインを作らず、古い判定結果では開かない |

繰り返し起動ではメインを再利用する。\
左の選択と作成に成功した後は両画面を開き、ユーザー設定に保存したパスを再起動後も使う。\
未設定時の明示的な開くコマンドも、左の入口へ接続する。

## 既存メインの扱い

不在や設定解除で既存メインを強制終了しない。\
直前の表示と Task 追加、詳細編集の下書きを保持し、操作ボタンのない接続状態とエラーだけを示す。\
新しい接続の空の初期状態でも表示を消さず、設定解除後は古い欠落パスと読込エラーを消す。\
欠落中の保存は既存の Extension 側の検証で拒否し、入力を残す。\
復元すると既存の監視で通常表示へ戻る。\
閉じているメインは外部の復元だけで自動表示せず、メニュー、コマンドまたは Event 選択で開く。\
この判断により、同じ設定案内が2箇所に出ることと、未保存入力の喪失を防ぐ。

## 検証

新規18テストを旧実装へ適用し、15件の失敗を確認した。\
元から成功した3件は設定済みの再利用と、構文不正、Project 欠落をエラーとして扱う場合である。\
設定解除後の古い欠落パスと読込エラーについても期待値を強め、修正前の失敗を確認した。

最終状態の全体検査は99ファイル、250テストである。\
lint、型検査、FSD、全テスト、ビルド、7 capability の厳格仕様とトレースを確認する。\
監視通知前の削除と復元、初回判定中に設定が変わるケース、反復起動、選択と作成、設定後の再起動も実 Extension ハンドラで確認した。\
既存の両画面案内テストは新しい仕様へ変更し、設定の取消、作成失敗、YAML の保全、監視とユーザー設定の検査は維持した。\
元の無条件起動の1テストは、新しい起動のテストへ統合した。

実ブラウザーは両テーマで8組合せを確認し、左のボタンの視認性とキーボード操作、既存メインのボタン非表示を検査する。\
実セッションと一時 YAML の欠落、復元と設定解除でも、既存メインの下書きと設定案内の非重複を確認する。\
欠落中の保存では Project YAML の全バイト列が同じであり、復元後も下書きが残る。\
通常の反復追加、取消、保存失敗からの再送、削除と左右の対象保全も回帰確認する。\
検査コマンドは変更せず、既存 UI 検査を新しい案内配置と保全の確認へ更新した。

## 最終操作確認

[manual-checks.md](../openspec/manual-checks.md) の隔離したプロファイルと新しい管理データを使う。

1. 未設定でメニューと開くコマンドを繰り返し、左だけに案内が出ることを確認する。
2. 左で選択または作成し、両画面が開くこと、再起動後も同じデータを案内なしで開くことを確認する。
3. 設定済みの検証用管理ファイルを移動し、メインを閉じてからメニューを開き、新しいメインが作られないことを確認する。
4. 既存メインに追加と詳細の下書きを残し、検証用ファイルの欠落と設定解除でも保持すること、設定ボタンが左だけに1組あることを確認する。
5. 復元後に操作を続けられることと、構文不正、権限、Project の欠落では設定案内を出さずエラーを示すことを確認する。

実 VS Code の最終 GUI 確認は利用者が行う。\
push、Marketplace 公開、README への画面キャプチャ追加は行っていない。
