# GlitchBoard - Product

## 目的

GlitchBoardは、1人で複数のプロジェクトを回すための個人用VS Code拡張機能である。\
タスクを階層で整理し、期限切れ、作業量の溢れ、作業の重なりを視覚的に把握する。\
追加・変更・削除・抽出を少ない操作で行えるようにする。\
生成AIの活用で個人が複数の仕事を並行する状況を想定し、チーム向けツールに伴う入力や設定の負担を避ける。

## 対象範囲と対象外

対象は、個人で管理できる規模のタスク、VS Code上の表示と操作、管理専用Gitリポジトリ内のテキストファイルへの保存である。\
どのフォルダをVS Codeで開いていても、設定した`manage.yaml`から同じボードを表示する。\
次は対象外とする。

- リアルタイム共有と同時編集の競合解決。\
  閲覧者はGitからファイルを取得する。
- メール、ポップアップなどの通知。\
  危険は画面上の色で示す。
- 独自の履歴管理や復元機能。\
  履歴と復元にはGitを使う。
- 項目を表形式で並べるだけのUI。
- 縦長画面への最適化。

## 管理モデル

基本は Project > Event > Task とする。\
Task を Event へ直接追加でき、必要なときだけ Story を作って Event > Story > Task として整理する。\
「Taks」は直接 Task の表示名であり、自動 Story は保存しない。\
旧版の管理ファイルの移行、互換性と旧版へ戻す保証は対象外とする。

Project は名前と色、Event は名前と必須の期限、Story は名前、Task は名前と任意のポイント、完了日を持つ。\
すべてに任意の補足を持つ。\
Project 詳細の編集でアーカイブを保存すると、PROJECT 一覧の行と期限マーカーだけを非表示にし、再起動後も維持する。\
EVENT 一覧、選択、関連データと読み込み対象の集計を維持し、再表示と復元の UI は置かない。\
ポイントは1、2、3、5、8、13、21から選び、未見積は計算上3ptとする。\
直接 Task と Story 内 Task を表示、削除、進捗とすべての計算へ等しく含める。

## 画面と操作

EVENT一覧はVS Code標準のサイドバーに常設する。\
メニュー表示では管理ファイルの判定を待ち、設定済みで不在でない場合だけメインパネルも開く。\
未設定と管理ファイル不在では設定案内を左だけに表示する。\
GlitchBoardはエディタタブに開き、ヘッダー、タイムライン、詳細エリアの3段で構成する。\
詳細パネルはボードの右側から重ねて表示する。\
VS Codeのダーク・ライトテーマに追従し、プロジェクト色を使い、危険な箇所だけ赤くする。

| 領域 | 主な内容と操作 |
| --- | --- |
| ヘッダー | 3日・1週間・月の表示期間、実績ペース、直近10稼働日の棒グラフ、期間負荷、危険件数 |
| タイムライン | 日付列、Projectごとの段、Event期限日の◆、今日・休日の列、最下段の必要ペースグラフ |
| EVENT一覧 | 期限順のEvent、期限切れ・今週・今後・完了済みのグループ、抽出条件と件数 |
| 詳細エリア | 選択Eventの要約、Story一覧、Task一覧 |
| 詳細パネル | 全階層共通の補足・編集・削除、Taskのポイント、Projectの色 |

3日と1週間は今日を起点とし、月は当月の1日から末日までとする。\
日付見出しと Project 見出しは縦スクロール中もタイムライン上端、必要ペースのグラフは下端に表示する。\
固定部分と行操作の高さを確保し、収まらない画面ではボード全体をスクロール可能にする。\
Project、Story と Task は専用ハンドルと上下キーで並べ替える。\
Story は同じ Event 内、Task は同じ所属内に限り、Taks は先頭固定とする。\
Project 名セルの右端で列幅、下端で全 Project 共通の行高を調整し、寸法スライダーは置かない。\
寸法は同じ VS Code プロファイルのタブの開き直しと再起動でも維持でき、期限切れは左の EVENT 一覧で扱いタイムラインに列を作らない。\
上部の Event 追加は設けず、Event は左の一覧で追加する。\
下部の見出しは Story、直接 Task の仮想グループ名は正確に Taks とする。\
同じProjectの同じ日に複数のEventがある場合は◆をまとめ、件数バッジから一覧を開く。\
3日・1週間表示では各◆に含まれる全Event名を出し、月表示では選択中のEventにだけラベルを出す。\
EVENT一覧の「今週」は今日から今週の日曜までとし、完了済みは抽出条件が「すべて」の場合だけ表示する。\
抽出条件は対象の「未完了 + 今後」または「すべて」と、読み込むProjectである。\
Projectの読み込み設定は`manage.yaml`に保存し、ボード全体へ反映する。\
読み込みを外したProjectも抽出条件にはファイルに保存された名前を表示する。\
危険なものだけに絞る抽出条件は設けない。\
条件を変更したときは漏斗ボタンに件数バッジを付け、見出しの下に現在の条件と件数を示す。\
EVENT一覧の行を選ぶと、ボードでそのEventを選択する。\
Event選択時は、未完了Taskを持つ最初のStoryを選ぶ。\
Event要約には残り日数、完了予測日、残りポイントと未見積件数、消化ポイントを示す。\
期限接近・期限切れ・溢れに当たるEventの要約は赤で示す。\
StoryにはTask完了数とポイント進捗、Taskには完了チェックとポイントバッジを示す。\
追加は各階層の見出しの「+」からその場で入力し、Enterで確定、Escで取り消す。\
追加の入力欄は保存成功後に閉じ、失敗時は入力値を残して画面上部に理由を表示する。\
追加先が変わる移動では、元の追加先へ追加、破棄、キャンセルを確認し、キャンセルでは選択と下書きを維持する。\
Project追加時は名前と色、Event追加時は名前・Project・期限、StoryとTask追加時は名前を入力する。\
EventのProjectの初期値は選択中のEventのProjectとし、Taskのポイントは未見積から始める。\
Taskのポイントはバッジから7段階のスライダーまたは数字を選び、完了状態はチェックで切り替える。\
ポイント変更後は完了予測と危険判定をすぐに再計算する。\
完了時には当日を`doneAt`に記録し、解除時には消す。\
名前、期限、補足などは詳細パネルで編集する。\
レコードの名前と全体を選ぶと下位情報を表示し、PROJECT 名列、左の EVENT と下部の実レコードに共通の詳細ボタンを置く。\
日付セルと同日 Event 一覧には詳細ボタンを置かず、◆と一覧から選択する。\
詳細が開いている間は選択先へ追従し、編集中は保存、破棄、キャンセルを確認して入力を守る。\
削除は物理削除とし、子孫を含む件数を示す確認ダイアログの後に行う。\
保存や削除に失敗した場合は画面上部に理由を表示する。\
全階層の詳細ボタンは共通の形とし、未選択では補足があれば青、なければグレーで示す。\
選択中の Project、Event、Task の詳細ボタンは Story と同じテーマの選択前景で強調する。\
左の Event 一覧と Task は選択背景を維持し、Story の選択行は他の選択行と同じ役割の明るい背景にし、選択枠は付けない。\
下部の Event 要約には選択背景を付けず、詳細ボタンの強調を維持する。\
キーボードフォーカスは操作対象の枠で区別し、選択枠と混同しない。\
Project 名と Task 名のホバー下線を外し、Project の名前セル全体はポインターカーソルとする。\
Project の選択左線の設定色を保ち、Event は左右の一覧、マーカーと下部の要約で選択先を示す。\
空の Project の選択が確定した場合だけ左右の Event 選択を解除し、Project 自体の選択を維持する。\
詳細パネルには所属 Project 名と設定色、対象種別と名前、階層、主要な数字3つ、補足、保存・編集・削除を置き、Escまたは×で閉じる。\
補足がない場合は「+ 補足を追加」を表示する。

`manage.yaml`が未設定なら EVENT 一覧だけで既存ファイルの選択と新規作成を案内する。\
既存メインは不在や設定解除で閉じず、表示と下書きを保ち、設定ボタンを重複して置かない。\
設定先の変更はVS Codeの再起動なしで反映し、日付が変わった後は今日を基準とする計算と表示を更新する。

## 負荷と危険の基本原則

稼働日は設定された休日を除く日とし、日本の祝日を休日にするかも設定で選ぶ。\
すべての計算は読み込み対象のProjectだけを使い、完了Taskを残作業から除く。Taskが1件もないEventは期限判定では未完了として扱う。\
実績ペースは直近10稼働日に完了したTaskのポイント合計を10で割ったpt/稼働日である。\
最初のTask完了日から10稼働日が経過するまでは「学習中」とする。\
学習中は実績ペース、期間負荷、完了予測日を表示せず、溢れと重なりを判定しない。\
期限接近と期限切れは学習中でも判定し、必要ペースグラフも表示する。\
学習中のグラフには実績ペースの破線と赤い塗りを出さない。\
完了予測は、未完了Eventを期限の早い順に並べ、今日から稼働日ごとに実績ペース分を先頭のEventから消化して算出する。\
必要ペースは、Eventの残りポイントを今日から期限までの稼働日に均等配分し、Event間で日ごとに合算する。\
期限切れEventの残りは、今日が稼働日なら今日、休日なら次の稼働日に載せる。\
グラフは休日も列として残し、非稼働日の値を0にする。\
実績ペースを超える部分だけ赤く塗り、一番高い日にだけ、枠と背景の塗りを付けずにpt付きの文字で数値を示す。\
期間負荷は、表示期間の必要ペースの合計を`表示期間のうち今日以降の稼働日数 × 実績ペース`で割った百分率とし、100%超を赤で示す。

| 判定 | 条件 | 表示 |
| --- | --- | --- |
| 期限接近 | 未完了で期限まで0〜3日 | ◆の赤い光、残り日数とEVENT一覧の赤字 |
| 期限切れ | 未完了で期限を過ぎた | ◆の赤い光、「n日超過」とEVENT一覧の赤字 |
| 溢れ | 完了予測日が期限後 | 完了予測日の赤字、◆の赤い光 |
| 重なり | その日の必要ペースが実績ペースを超える | グラフの赤い面、日付列の薄い赤 |

期限まで4〜7日は黄色の注意表示とし、危険件数に含めない。\
危険件数は、期限接近・期限切れ・溢れのいずれかに当てはまるEventの重複を除いた数に、表示期間内に重なりが1日でもあれば1を加える。
