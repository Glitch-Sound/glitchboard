# GlitchBoard - Product

## 目的

GlitchBoardは、1人で複数のプロジェクトを回すための個人用VS Code拡張機能である。\
タスクを階層で整理し、期限切れ、作業量の溢れ、作業の重なりを視覚的に把握する。\
追加・変更・削除・抽出を少ない操作で行えるようにする。\
生成AIの活用で個人が複数の仕事を並行する状況を想定し、チーム向けツールに伴う入力や設定の負担を避ける。

## 対象範囲と対象外

対象は、個人で管理できる規模のタスク、VS Code上の表示と操作、管理専用Gitリポジトリ内のテキストファイルへの保存である。\
どのフォルダをVS Codeで開いていても、設定した`manage.yaml`から同じボードを表示する。\
次は対象外とする。

- リアルタイム共有と同時編集の競合解決。\
  閲覧者はGitからファイルを取得する。
- メール、ポップアップなどの通知。\
  危険は画面上の色で示す。
- 独自の履歴管理や復元機能。\
  履歴と復元にはGitを使う。
- 項目を表形式で並べるだけのUI。
- 縦長画面への最適化。

## 管理モデル

階層は`Project > Event > Story > Task`とする。\
各親は複数の子を持てる。

| 階層 | 意味 | 主な属性 |
| --- | --- | --- |
| Project | プロジェクトの種類 | 名前、色 |
| Event | 期限またはマイルストーン | 名前、必須の期限日 |
| Story | 作業のまとまり | 名前、期間は持たず、期限は親Eventに従う |
| Task | 実際の作業単位 | 名前、任意のポイント、任意の完了日 |

ポイントはTaskだけが保持し、StoryとEventの値は配下のTaskから集計する。\
ポイントの選択肢は`1, 2, 3, 5, 8, 13, 21`とする。\
未見積のTaskは計算上3ptとみなす。\
ポイントの色は1・2が青、3・5が緑、8・13がオレンジ、21が赤紫であり、危険を示す赤と区別する。

## 画面と操作

EVENT一覧はVS Code標準のサイドバーに常設する。\
GlitchBoardはエディタタブに開き、ヘッダー、タイムライン、詳細エリアの3段で構成する。\
詳細パネルはボードの右側から重ねて表示する。\
VS Codeのダーク・ライトテーマに追従し、プロジェクト色を使い、危険な箇所だけ赤くする。

| 領域 | 主な内容と操作 |
| --- | --- |
| ヘッダー | 3日・1週間・月の表示期間、実績ペース、直近10稼働日の棒グラフ、期間負荷、危険件数 |
| タイムライン | 日付列、Projectごとの段、Event期限日の◆、今日・休日の列、最下段の必要ペースグラフ |
| EVENT一覧 | 期限順のEvent、期限切れ・今週・今後・完了済みのグループ、抽出条件と件数 |
| 詳細エリア | 選択Eventの要約、Story一覧、Task一覧 |
| 詳細パネル | 全階層共通の補足・リンク・編集・削除、Taskのポイント、Projectの色 |

3日と1週間は今日を起点とし、月は当月の1日から末日までとする。\
同じProjectの同じ日に複数のEventがある場合は◆をまとめ、件数バッジから一覧を開く。\
月表示では選択中のEventにだけマーカーのラベルを出す。\
EVENT一覧の「今週」は今日から今週の日曜までとし、完了済みは抽出条件が「すべて」の場合だけ表示する。\
抽出条件は対象の「未完了 + 今後」または「すべて」と、読み込むProjectである。\
Projectの読み込み設定は`manage.yaml`に保存し、ボード全体へ反映する。\
危険なものだけに絞る抽出条件は設けない。\
条件を変更したときは漏斗ボタンに件数バッジを付け、見出しの下に現在の条件と件数を示す。\
EVENT一覧の行を選ぶと、ボードでそのEventを選択する。\
Event選択時は、未完了Taskを持つ最初のStoryを選ぶ。\
Event要約には残り日数、完了予測日、残りポイントと未見積件数、消化ポイントを示す。\
StoryにはTask完了数とポイント進捗、Taskには完了チェックとポイントバッジを示す。\
追加は各階層の見出しの「+」からその場で入力し、Enterで確定、Escで取り消す。\
Project追加時は名前と色、Event追加時は名前・Project・期限、StoryとTask追加時は名前を入力する。\
EventのProjectの初期値は選択中のEventのProjectとし、Taskのポイントは未見積から始める。\
Taskのポイントはバッジから7段階のスライダーまたは数字を選び、完了状態はチェックで切り替える。\
ポイント変更後は完了予測と危険判定をすぐに再計算する。\
完了時には当日を`doneAt`に記録し、解除時には消す。\
名前、期限、補足などは詳細パネルで編集する。\
削除は物理削除とし、子孫を含む件数を示す確認ダイアログの後に行う。\
全階層の詳細ボタンは共通の形とし、補足があれば青、なければグレーで示す。\
詳細パネルには種別と階層、主要な数字3つ、補足とリンク、保存・編集・削除を置き、Escまたは×で閉じる。\
補足がない場合は「+ 補足を追加」を表示する。

## 負荷と危険の基本原則

稼働日は設定された休日を除く日とし、日本の祝日を休日にするかも設定で選ぶ。\
すべての計算は読み込み対象のProjectだけを使い、完了Taskを残作業から除く。\
実績ペースは直近10稼働日に完了したTaskのポイント合計を10で割ったpt/稼働日である。\
最初のTask完了日から10稼働日が経過するまでは「学習中」とする。\
学習中は実績ペース、期間負荷、完了予測日を表示せず、溢れと重なりを判定しない。\
期限接近と期限切れは学習中でも判定し、必要ペースグラフも表示する。\
学習中のグラフには実績ペースの破線と赤い塗りを出さない。\
完了予測は、未完了Eventを期限の早い順に並べ、今日から稼働日ごとに実績ペース分を先頭のEventから消化して算出する。\
必要ペースは、Eventの残りポイントを今日から期限までの稼働日に均等配分し、Event間で日ごとに合算する。\
期限切れEventの残りは今日に載せる。\
グラフは休日も列として残し、非稼働日の値を0にする。\
実績ペースを超える部分だけ赤く塗り、一番高い日にだけ数値を示す。\
期間負荷は、表示期間の必要ペースの合計を`表示期間の稼働日数 × 実績ペース`で割った百分率とし、100%超を赤で示す。

| 判定 | 条件 | 表示 |
| --- | --- | --- |
| 期限接近 | 未完了で期限まで0〜3日 | ◆の赤い光、残り日数とEVENT一覧の赤字 |
| 期限切れ | 未完了で期限を過ぎた | ◆の赤い光、「n日超過」とEVENT一覧の赤字 |
| 溢れ | 完了予測日が期限後 | 完了予測日の赤字、◆の赤い光 |
| 重なり | その日の必要ペースが実績ペースを超える | グラフの赤い面、日付列の薄い赤 |

期限まで4〜7日は黄色の注意表示とし、危険件数に含めない。\
危険件数は、期限接近・期限切れ・溢れのいずれかに当てはまるEventの重複を除いた数に、表示期間内に重なりが1日でもあれば1を加える。
