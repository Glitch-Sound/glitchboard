# vscode-integration Specification

## Purpose

VS Code拡張の表示基盤は、個人が複数Projectの作業をVS Codeで管理する際に、どのワークスペースでも同じ管理データへ接続し、サイドバーとエディタで操作できる土台を作る。\
この機能は管理対象の状態と画面の振る舞いを一貫して扱う。

## Requirements

### Requirement: REQ-012 - 二つの表示面

WHEN 拡張を起動したとき、GlitchBoardは SHALL EVENT一覧をVS Codeサイドバーに常設し、コマンドとサイドバーの表示時には管理ファイルの判定完了を待ち、設定済みで管理ファイルが不在でない場合だけGlitchBoardをエディタタブに開く。\
未設定または管理ファイル不在では EVENT 一覧だけを表示し、新しいメインを作成しない。\
繰り返し表示してもメインパネルを重複作成しない。

#### Scenario: REQ-012-S01 - 表示面を開く

- **GIVEN** VS Code安定版で拡張が有効で、管理ファイルが設定済みで存在する。
- **WHEN** GlitchBoardを開くコマンドを実行する。
- **THEN** サイドバーのEVENT一覧とエディタタブのボードが表示される。

#### Scenario: REQ-012-S02 - メニューから両画面を表示

- **GIVEN** 管理ファイルが設定済みで存在し、GlitchBoard のサイドバーが閉じている。
- **WHEN** メニューから GlitchBoard を選ぶ。
- **THEN** EVENT 一覧とメインパネルが表示され、再度選んでもパネルは1つである。

#### Scenario: REQ-012-S03 - 設定前の繰り返し起動

- **GIVEN** 管理ファイルが未設定か、設定先の管理ファイルが存在しない。
- **WHEN** メニューまたは開くコマンドを繰り返し実行する。
- **THEN** EVENT 一覧だけを表示し、メインを新規作成せず、判定前にもメインを開かない。

#### Scenario: REQ-012-S04 - 設定後の起動

- **GIVEN** 左の案内から有効な管理ファイルを選択または作成した。
- **WHEN** 設定を完了するか、拡張を再起動してメニューを選ぶ。
- **THEN** 同じ設定の両画面を表示し、設定案内を表示せず、メインを重複作成しない。

### Requirement: REQ-013 - 状態同期と外部変更

WHEN YAMLが変更されたとき、GlitchBoardは SHALL 再読込と検証を行い、ボードとEVENT一覧へ同じデータ版を配信する。\
選択項目がなくなった場合は選択を解除する。\
`glitchboard.manageFile`の設定変更時は接続先とファイル監視を切り替え、両画面を再読み込みする。\
異なる接続先の欠落中に保持する前の表示は読取専用とする。\
同じ管理ファイルの再設定では有効な選択と下書きを保持する。\
別の管理ファイルへの変更は、元のファイルへの保存、破棄、キャンセルを確認してから確定し、失敗とキャンセルでは接続状態、選択と未保存内容を保つ。\
日本時間の日付が変わった後は、今日を基準とする計算と表示を更新する。

#### Scenario: REQ-013-S01 - 外部変更

- **GIVEN** 選択中EventのYAMLをエディタ外で削除した。
- **WHEN** ファイル監視が変更を検知する。
- **THEN** 両画面からEventが消え選択状態が解除される。

#### Scenario: REQ-013-S02 - 不正な外部変更

- **GIVEN** 外部編集後のYAMLが不正である。
- **WHEN** 変更を検知する。
- **THEN** 直前の有効な表示を維持しエラーを示す。

#### Scenario: REQ-013-S03 - 管理ファイルの切り替え

- **GIVEN** ボードとEVENT一覧を開き、未保存の入力がない。
- **WHEN** `glitchboard.manageFile`を別のファイルへ変更する。
- **THEN** VS Codeの再起動なしで新しい管理データを両画面へ反映し、監視対象も切り替わる。

#### Scenario: REQ-013-S04 - 日付変更

- **GIVEN** ボードまたはEVENT一覧を開いたまま日本時間の日付が変わる。
- **WHEN** 画面が現在日を確認する。
- **THEN** 今日の列、期限までの日数、必要ペース、危険判定を新しい日付で更新する。

#### Scenario: REQ-013-S05 - 同じファイルへの再設定

- **GIVEN** 2件以上の Event があり、既定以外の Event の Story を選択して Task 追加と詳細編集の下書きを入力した後、管理設定を解除している。
- **WHEN** 左の案内から同じ管理ファイルを選択する。
- **THEN** 元の Event と Story の選択、Task 追加と詳細編集の入力を保ち、同じファイルへ接続する。
- **AND** 繰り返し選択しても初期 Event へ戻らず、次の追加は元の Story へ保存される。

#### Scenario: REQ-013-S06 - 別ファイルへの変更の取消

- **GIVEN** 元の Event に Task 追加と詳細編集の下書きがあり、管理設定を解除している。
- **WHEN** 別の管理ファイルを選び、未保存内容の確認をキャンセルする。
- **THEN** 管理設定は未設定のままで、元の Event と Story の選択、両方の下書き、元の YAML を維持する。
- **AND** 再操作でき、詳細確認をキャンセルした段階でも追加下書きを消さない。

#### Scenario: REQ-013-S07 - 元のファイルへ保存して変更

- **GIVEN** 管理設定を解除する前の Event と Story に未保存の追加または詳細編集がある。
- **WHEN** 別の管理ファイルを選び、未保存内容を保存して進む。
- **THEN** 元の管理ファイルに登録された元の Project と対象へ1回だけ保存し、成功後に設定、表示と監視を別の管理ファイルへ切り替える。
- **AND** 切替先の YAML に元の下書きを保存しない。

#### Scenario: REQ-013-S08 - 再設定時の保存失敗

- **GIVEN** 別の管理ファイルへの変更確認を表示し、元のファイルへの保存が失敗する状態である。
- **WHEN** 保存して進む操作を行う。
- **THEN** 接続変更を確定せず、元の選択と未保存内容を保ち、失敗を表示する。
- **AND** 再試行またはキャンセルでき、成功済みの入力を重複保存しない。

#### Scenario: REQ-013-S09 - 破棄して別データへ変更

- **GIVEN** 別の管理ファイルが元のファイルと同じ Project 参照と UUID を使い、元の Event に下書きがある。
- **WHEN** 未保存内容を破棄して別のファイルへ進む。
- **THEN** 元の YAML を書き換えず、新しいデータの初期選択と内容を表示し、元の入力と詳細選択を引き継がない。

#### Scenario: REQ-013-S10 - 設定画面からの変更確認

- **GIVEN** ボードに未保存の入力があり、管理ファイルを設定済みである。
- **WHEN** VS Code の設定で別ファイルを指定し、未保存内容の確認をキャンセルする。
- **THEN** 元の管理ファイルの設定と監視、表示と入力を維持する。

#### Scenario: REQ-013-S11 - Project 追加中の接続変更

- **GIVEN** ボードの Project 追加欄に名前と色を入力している。
- **WHEN** 別の管理ファイルへ変更する。
- **THEN** 元のファイルへ追加、破棄、キャンセルを確認し、キャンセルと追加失敗では名前と色を保持する。

#### Scenario: REQ-013-S12 - 切替先欠落中の前の表示

- **GIVEN** 別の管理ファイルへの変更を確定した後、切替先が欠落している。
- **WHEN** 前の管理データの表示を保持する。
- **THEN** 前の接続の表示であることを明示し、そこへの新しい入力を受け付けない。
- **AND** 切替先の復元で新しい管理データを表示して操作可能に戻し、同じ接続の欠落時の下書き保持は変更しない。

### Requirement: REQ-014 - 検証済みメッセージ

WHEN Webviewから操作を受けたとき、GlitchBoardは SHALL 共有スキーマでメッセージを検証し、未知または不正な操作を拒否する。
保存や削除の結果を画面へ返し、失敗理由を画面上部に表示する。

#### Scenario: REQ-014-S01 - 不正なポイント

- **GIVEN** Webviewからpoints:4の更新要求が届く。
- **WHEN** Extensionがメッセージを受ける。
- **THEN** 保存せず検証エラーを返す。

#### Scenario: REQ-014-S02 - 操作結果の表示

- **GIVEN** 保存または削除が拡張側で失敗した。
- **WHEN** 失敗理由をWebviewへ返す。
- **THEN** 操作した画面の上部に理由を表示する。

### Requirement: REQ-029 - 管理ファイル未設定時の案内

WHEN `glitchboard.manageFile`が未設定、または設定先の管理ファイルが存在しないと判明したとき、GlitchBoardは SHALL EVENT一覧だけに、背景、枠、余白を持つ「manage.yamlを選ぶ」「新しく作る」ボタンを提示する。\
不在時は理由と設定先パスを表示する。\
ボタンはダーク・ライトテーマで判別でき、ホバーとキーボードフォーカスを示し、Tabで移動してEnterまたはSpaceで操作できる。\
選択または作成後は設定へ保存し、管理データを読み込んで両画面を表示する。\
既存メインは未設定と不在で強制終了せず、有効な表示と下書きを保持し、設定ボタンを重複して表示しない。\
取消時は設定とファイルを変更せず、作成失敗時は理由を表示し、いずれも再操作できる状態を維持する。\
利用中の不在検知では直前の有効な表示を保持して EVENT 一覧だけに案内を追加し、元のパスへの復元後は通常表示へ戻す。\
Projectファイルの欠落、構文不正、権限エラーは管理ファイル不在と区別し、既存のエラー表示と保全を維持する。

#### Scenario: REQ-029-S01 - 未設定

- **GIVEN** `glitchboard.manageFile`が未設定である。
- **WHEN** EVENT一覧を開く。
- **THEN** 「manage.yamlを選ぶ」と「新しく作る」をボタンとして表示する。
- **AND** ファイルの自動作成とダイアログの自動表示は行わない。

#### Scenario: REQ-029-S02 - 設定先が存在しない

- **GIVEN** `glitchboard.manageFile`に存在しない絶対パスが設定されている。
- **WHEN** 起動または設定変更による読込が完了する。
- **THEN** EVENT一覧に管理ファイルが見つからない理由と設定先パスを表示する。
- **AND** EVENT一覧だけに「manage.yamlを選ぶ」と「新しく作る」のボタンを表示する。
- **AND** 設定とファイルは変更しない。

#### Scenario: REQ-029-S03 - 利用中の管理ファイルの削除

- **GIVEN** 管理データを読み込み済みで、管理ファイルだけが外部から削除された。
- **WHEN** ファイル監視による再読込が完了する。
- **THEN** EVENT一覧だけに不在の理由、設定先パス、二つのボタンを表示する。
- **AND** 直前の有効な管理データと既存メインの下書きを維持し、メインに設定ボタンを表示しない。

#### Scenario: REQ-029-S04 - 既存ファイルの選択

- **GIVEN** 未設定または管理ファイル不在の案内が表示されている。
- **WHEN** 「manage.yamlを選ぶ」ボタンから開いたファイル選択ダイアログで有効な管理ファイルを選ぶ。
- **THEN** 選んだパスが`glitchboard.manageFile`へ保存される。
- **AND** 再起動なしで両画面と監視対象が切り替わり、新しい管理データを表示して案内を閉じる。

#### Scenario: REQ-029-S05 - 管理ファイルの新規作成

- **GIVEN** 未設定または管理ファイル不在の案内が表示され、保存先は存在しない書込可能なファイルパスである。
- **WHEN** 「新しく作る」ボタンから開いた保存ダイアログで保存先を確定する。
- **THEN** `settings.workdays_off: [sat, sun]`、`settings.public_holidays: true`、`projects: []`を持つ管理ファイルを作成する。
- **AND** 保存先を設定へ保存し、再起動なしで両画面を新しい管理データへ切り替えて案内を閉じる。

#### Scenario: REQ-029-S06 - ダイアログの取消

- **GIVEN** 案内のいずれかのボタンからファイルダイアログを開いている。
- **WHEN** ダイアログを取り消す。
- **THEN** 設定とファイルを変更しない。
- **AND** EVENT一覧の案内とボタンを維持し、再操作できる。

#### Scenario: REQ-029-S07 - 新規作成の失敗

- **GIVEN** 案内から新規作成の保存ダイアログを開き、既存ファイルまたは書込権限のない場所を指定している。
- **WHEN** 保存を確定する。
- **THEN** 既存ファイルを上書きせず、設定を変更しない。
- **AND** 操作した画面の上部に失敗理由を表示する。
- **AND** 案内とボタンを維持し、別の保存先の指定または既存ファイルの選択を再操作できる。

#### Scenario: REQ-029-S08 - 不在とその他のエラーの区別

- **GIVEN** 管理ファイルは存在し、Projectファイルの欠落、YAML構文不正、または読込権限エラーがある。
- **WHEN** データの再読込が完了する。
- **THEN** 管理ファイル不在の案内を表示せず、該当エラーを表示する。
- **AND** 直前の有効な表示がある場合は維持し、ファイルを書き換えない。

#### Scenario: REQ-029-S09 - ボタンの視認性とキーボード操作

- **GIVEN** ダークまたはライトテーマで未設定または不在の案内が表示され、ボードまたは幅240pxのEVENT一覧を操作する。
- **WHEN** Tabで二つのボタンへ順に移動し、EnterまたはSpaceで操作する。
- **THEN** 二つのボタンの背景、枠、余白、フォーカス表示を判別できる。
- **AND** ラベルと操作領域が欠けず、横スクロールなしで両方に到達できる。
- **AND** それぞれに対応するファイルダイアログが開く。
- **AND** ポインターを重ねた際にもボタンの背景が変化する。

#### Scenario: REQ-029-S10 - 元のパスへの復元

- **GIVEN** 管理ファイル不在の案内が表示され、元の設定先へ有効な管理ファイルを復元した。
- **WHEN** ファイル監視による再読込が完了する。
- **THEN** 設定を変更せず、両画面で復元した管理データを表示し、不在の案内を閉じる。

#### Scenario: REQ-029-S11 - 既存メインでの未設定

- **GIVEN** メインで下書きを入力している。
- **WHEN** 管理ファイル設定が解除される。
- **THEN** メインを閉じず表示と下書きを保持し、設定ボタンは EVENT 一覧だけに表示する。

#### Scenario: REQ-029-S12 - 案内の重複を防ぐ

- **GIVEN** 既存メインと EVENT 一覧が表示されている。
- **WHEN** 未設定または管理ファイル不在の状態を受け取る。
- **THEN** 設定案内の領域と2つの設定ボタンは EVENT 一覧だけに1組あり、メインには接続状態かエラーだけを表示する。

### Requirement: NREQ-001 - オフライン動作

WHILE 通信を遮断した環境で利用するとき、GlitchBoardは SHALL ローカルYAMLの読込、表示、編集を外部通信なしで完了する。

#### Scenario: NREQ-001-S01 - ネットワーク遮断

- **GIVEN** ネットワークを無効にし有効な管理データがある。
- **WHEN** ボードを開きTaskを編集する。
- **THEN** 外部要求0件で編集結果がYAMLに保存される。

### Requirement: REQ-039 - 管理ファイルの共有設定と監視

WHEN 管理ファイルを選択または作成したとき、GlitchBoard はユーザー設定に保存し、別のワークスペースでも同じ設定先を利用しなければならない(SHALL)。\
選択可能な yaml と yml の管理ファイルおよび Project ファイルについて、外部の変更、作成、削除を監視しなければならない(SHALL)。

#### Scenario: REQ-039-S01 - 別ワークスペースで同じ設定

- **GIVEN** 作業フォルダを開いて管理ファイルを選択または作成する。
- **WHEN** 別の作業フォルダへ切り替える。
- **THEN** 同じユーザー設定の管理ファイルを読み、ワークスペース設定には保存しない。

#### Scenario: REQ-039-S02 - 両拡張子の監視

- **GIVEN** yaml または yml の管理ファイルと Project がある。
- **WHEN** ファイルを外部で変更、作成または削除する。
- **THEN** 実際に登録した監視パターンがそのファイルに一致し、両画面が再読込結果を表示する。
