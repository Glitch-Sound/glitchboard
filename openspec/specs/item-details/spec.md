# item-details Specification

## Purpose

共通詳細パネルは、個人が複数Projectの作業をVS Codeで管理する際に、全階層の補足と編集操作を共通の詳細パネルから行えるようにする。\
この機能は管理対象の状態と画面の振る舞いを一貫して扱う。

## Requirements

### Requirement: REQ-026 - 詳細パネルの表示
WHEN どの階層の詳細ボタンを押したときも、GlitchBoardは SHALL 右側のパネルに種別と階層、主要指標3つ、補足、編集と削除を示す。\
補足があれば詳細ボタンを青、なければ灰色とし、補足なしでは「+ 補足を追加」を示す。\
Taskにはポイント、Projectには色の編集部品を示し、Escまたは×で閉じる。\
上部は対象 Project の名前と設定色を共通タイトルにし、その下に EVENT : 名前のような種別と対象名、階層を示し、主要指標は3枚のカードで示す。\
Taskのポイントは Task 一覧と同じ配色、バッジ、スライダー、数値と未見積の選択で編集し、「補足」は区切り線付きの見出しとする。\
下部の編集と削除は間隔を空けた独立ボタンにする。

#### Scenario: REQ-026-S01 - 補足あり

- **GIVEN** noteを持つStoryがある。
- **WHEN** 青い詳細ボタンを押す。
- **THEN** 右側にStoryの詳細が開く。

#### Scenario: REQ-026-S02 - 補足なし

- **GIVEN** noteがないTaskがある。
- **WHEN** 灰色の詳細ボタンを押す。
- **THEN** + 補足を追加が表示される。

#### Scenario: REQ-026-S03 - 共通の所属表示とポイント

- **GIVEN** Project、Event、Story、Task が同じ Project に属している。
- **WHEN** 各詳細を表示する。
- **THEN** すべてで Project 名と設定色、対象種別と名前を表示し、Task のポイントは一覧と同じ操作と配色で変更できる。

#### Scenario: REQ-026-S04 - 明暗の設定色でも読める所属

- **GIVEN** Project 色が白、黒または淡色であり、ダークまたはライトの詳細を表示する。
- **WHEN** 所属 Project 名を表示する。
- **THEN** 設定色の枠をそのまま保ち、タイトル文字はテーマの前景へ寄せた設定色で表示して背景と区別できる。
- **AND** Project の保存色と他のマーカーの色は変更しない。

### Requirement: REQ-027 - 詳細編集

WHEN 詳細パネルで編集を保存したとき、GlitchBoardは SHALL 名前、Event期限、Project色、Taskポイントを種類に応じて検証し、YAMLに保存して各表示と計算へ反映する。
Eventの期限欄では、追加欄と共通のWebview内カレンダーで日付を選べ、`YYYY-MM-DD`の直接入力も受け付ける。\
`showPicker()`が存在しない場合や例外となる環境でも期限を選べ、未入力または実在しない日付の保存要求は送信しない。\
日付の選択だけでは保存せず、保存を確定したときに選んだ暦日を反映する。\
カレンダーが開いている間のEscや枠外クリックはカレンダーだけを閉じ、詳細パネルと編集内容を保持する。

#### Scenario: REQ-027-S01 - 期限変更

- **GIVEN** Eventの期限が2026-11-10である。
- **WHEN** パネルで2026-11-12へ変更する。
- **THEN** タイムラインの◆と危険判定が更新される。

#### Scenario: REQ-027-S02 - Project色変更

- **GIVEN** 青いProjectがある。
- **WHEN** パネルで緑を選ぶ。
- **THEN** Project色が保存されマーカーも緑になる。

#### Scenario: REQ-027-S03 - 期限編集への横展開

- **GIVEN** Eventの詳細編集で期限が`2026-11-10`であり、`showPicker()`が存在しないか`SecurityError`を投げる環境である。
- **WHEN** 期限の選択操作を開く。
- **THEN** 共通のカレンダーに2026年11月と選択中の10日を表示する。
- **AND** 12日を選ぶと編集欄の期限は`2026-11-12`となり、保存操作までは保存要求を送信しない。
- **AND** 保存を確定すると同じ日付でYAML、タイムライン、危険判定を更新する。
- **AND** 直接入力、月移動、キーボード操作、両テーマでの表示も追加欄と同じ振る舞いとなる。
- **AND** 未入力または実在しない日付では理由を示し、保存要求を送らない。

#### Scenario: REQ-027-S04 - 期限編集のカレンダーだけを閉じる

- **GIVEN** 詳細パネルの編集中に名前と期限を変更し、カレンダーを開いている。
- **WHEN** Escを押すかカレンダーの枠外をクリックする。
- **THEN** カレンダーだけを閉じ、詳細パネルと編集中の名前と期限を保持する。
- **AND** Escで閉じた場合は期限の選択操作へフォーカスが戻る。
- **AND** 保存要求を送信せず、期限の選び直しや編集の継続ができる。

### Requirement: REQ-028 - 補足

WHEN 詳細パネルで補足を保存したとき、GlitchBoardは SHALL `note`の文章と箇条書きをProject YAMLに保存する。\
詳細パネルにリンク入力を表示せず、編集要求に `links` があれば拒否する。

#### Scenario: REQ-028-S03 - 補足の保存

- **GIVEN** 補足のないProjectを表示している。
- **WHEN** 文章と箇条書きを補足として保存する。
- **THEN** `note`だけを保存要求に含め、リンク入力を表示しない。


#### Scenario: REQ-028-S05 - 直接 Task の補足を読み戻す

- **GIVEN** Event 直下に Task がある。
- **WHEN** その Task の補足を保存して読み込む。
- **THEN** 補足は直接 Task に保存され、再読込後も同じ内容となる。

### Requirement: REQ-035 - レコードの選択と詳細
WHEN レコードをクリックまたはキーボードで選択したとき、GlitchBoard は紐づく下位情報を表示し、詳細が開いていればその対象へ切り替えなければならない(SHALL)。\
Project、Event、Story、Task と左の Event に共通の詳細ボタンを設け、詳細が閉じているときはレコード選択だけで開かず、詳細ボタンで開かなければならない。\
完了、ポイント、移動、削除などの独立した操作は親の選択や詳細操作を発火させてはならない。

#### Scenario: REQ-035-S01 - 名前と独立した操作

- **GIVEN** Project、Event、Story、Task のレコードが見えている。
- **WHEN** 名前、行の余白または詳細ボタンを実行する。
- **THEN** 名前と余白はそのレコードを選択し、詳細ボタンは対象の詳細を開く。\
  Project はその Event、Event は Story、Story は Task の情報を示す。
- **AND** 詳細表示中の別レコード選択では対象が切り替わり、完了とポイントの操作では対象が変わらない。

### Requirement: REQ-036 - 詳細編集の確実な保存と取消
WHEN 名前、期限、補足の編集を保存したとき、GlitchBoard は保存の結果を待ち、成功した場合だけ編集を閉じ、失敗時は入力を保持しなければならない(SHALL)。\
取消後は再開時点の保存済み値を表示しなければならない。\
Esc は最前面のカレンダー、削除確認、編集、詳細の順に現在の操作だけを扱い、編集中の終了は未保存確認を通し、詳細を閉じた後は元の操作にフォーカスを戻さなければならない。

#### Scenario: REQ-036-S01 - 保存失敗からの再操作

- **GIVEN** 名前または補足を編集している。
- **WHEN** 保存が失敗して再度保存する。
- **THEN** 失敗時は入力を残し、成功した後に編集を閉じる。

#### Scenario: REQ-036-S02 - 取消と再開

- **GIVEN** 保存済みの名前または補足を変更し、取消した。
- **WHEN** 編集を再び開く。
- **THEN** 未保存の変更を含まず、現在保存されている値を表示する。

#### Scenario: REQ-036-S03 - Esc とフォーカス

- **GIVEN** 詳細ボタンから詳細を開き、編集または削除確認が開いている。
- **WHEN** Esc を順に押す。
- **THEN** 最前面の操作だけを扱い、編集では未保存確認を示し、詳細を閉じた後は元の詳細ボタンにフォーカスが戻る。

### Requirement: REQ-041 - 編集中の移動確認
WHEN 詳細の編集中に別レコードの選択、詳細ボタン、終了または編集対象変更を要求したとき、GlitchBoard は保存して進む、破棄して進む、キャンセルを選べる確認を示し、無断で入力を破棄してはならない(SHALL)。\
左ペインからの要求も同じ確認を通す。\
保存失敗または検証失敗では元の対象と入力を維持し、成功した場合だけ要求先へ進む。\
保存中は二重保存と破棄を防ぎ、確認中の追加要求では最初の移動先を維持する。

#### Scenario: REQ-041-S01 - 保存して移動

- **GIVEN** 名前、期限または補足を編集中である。
- **WHEN** 別レコードを選び、保存して進む。
- **THEN** 元の対象へ編集を保存した後だけ、指定した対象の情報と詳細を表示する。

#### Scenario: REQ-041-S02 - 破棄とキャンセル

- **GIVEN** 編集中に移動確認が開いている。
- **WHEN** 破棄またはキャンセルを選ぶ。
- **THEN** 破棄では保存せず移動し、キャンセルでは元の対象と入力を保つ。

#### Scenario: REQ-041-S03 - 失敗と保存中

- **GIVEN** 編集中の移動確認から保存を行う。
- **WHEN** 検証または保存が失敗する。
- **THEN** 入力と移動先を保ち、保存中の追加要求は二重送信や入力消失を起こさず、再送できる。

#### Scenario: REQ-041-S04 - 左ペインからの切替

- **GIVEN** ボードで編集している。
- **WHEN** 左の別 Event の行または詳細を選ぶ。
- **THEN** 選択状態を変更する前に同じ確認を示し、キャンセルでは元の Event を維持する。
