# board-visualization Specification

## Purpose

ボードとタイムラインは、個人が複数Projectの作業をVS Codeで管理する際に、Project横断の期限、負荷、進捗を一画面で把握できるようにする。\
この機能は管理対象の状態と画面の振る舞いを一貫して扱う。

## Requirements

### Requirement: REQ-015 - 表示期間

WHEN 表示期間を切り替えたとき、GlitchBoardは SHALL 3日を今日から3暦日、1週間を今日から7暦日、月を当月1日から末日として表示する。
切り替えは3つの独立したボタンとし、選択中を強調する。

#### Scenario: REQ-015-S01 - 月末

- **GIVEN** 2026-11-03を今日とする。
- **WHEN** 月を選ぶ。
- **THEN** 11月1日から30日までの列を表示する。

### Requirement: REQ-016 - Project別の期限タイムライン
WHILE ボードを表示するとき、GlitchBoard は Project 行と日付列を設け、期限の Event を Project 色の◆で表示しなければならない(SHALL)。\
期限切れの列とマーカーは表示せず、期限切れ Event は EVENT 一覧から操作する。\
同一 Project の同日は◆の角に件数バッジを置く。\
3日と1週間は全 Event 名、月は選択 Event 名だけを表示する。\
今日と休日は別背景とし、今日は内容を隠さない薄い強調とする。\
期限接近、溢れは◆に赤い光、期限まで4〜7暦日は黄色で示す。\
見出しは曜日と日付の2段、月は日だけを表示し当月全列を横スクロールなしで収める。\
Project 名の前に色の丸、右端に操作ボタンを置く。\
通常行は全 Project 共通の調整可能な高さで名前、詳細、移動ハンドル、マーカーとラベルを収め、追加フォーム、日付見出し、グラフの行は除外する。

#### Scenario: REQ-016-S01 - 同日の複数Event

- **GIVEN** 同じProjectの同じ日に3件のEventがある。
- **WHEN** まとめた◆を選ぶ。
- **THEN** 3件の一覧が開き選んだEventが選択される。

#### Scenario: REQ-016-S02 - 月表示

- **GIVEN** 月表示で3件のEventがあり1件が選択中である。
- **WHEN** タイムラインを描く。
- **THEN** 選択中のEventだけにラベルが付く。

#### Scenario: REQ-016-S03 - 短期表示

- **GIVEN** 3日または1週間の表示に、未選択のEventがある。
- **WHEN** タイムラインを描く。
- **THEN** 未選択のEventを含む◆にも名前が表示される。

#### Scenario: REQ-016-S04 - 期限切れのEvent

- **GIVEN** 今日より前に期限を過ぎたEventが同じProjectに2件ある。
- **WHEN** ボードを表示する。
- **THEN** 「期限切れ」列と期限切れの◆を表示せず、EVENT 一覧で2件から選択できる。

#### Scenario: REQ-016-S05 - Project行の高さ

- **GIVEN** 幅1440px、高さ900pxの画面に通常の文字サイズで3件のProjectがあり、うち2件にEventマーカーと名前がある。
- **WHEN** ボードを表示する。
- **THEN** 各通常行の描画高さは共通の初期値で、Projectの詳細ボタン、移動ハンドルとEventマーカーが操作できる。
- **AND** 調整した高さをすべての通常行へ適用する。

#### Scenario: REQ-016-S06 - 月の補助詳細操作

- **GIVEN** 月表示で、期限の1日ごとの列が狭い。
- **WHEN** 期限のマーカーへポインターまたはキーボードフォーカスを移す。
- **THEN** 補助詳細ボタンをマーカーに重ねず上に表示し、1クリックまたは Tab と Enter で対象の詳細を開ける。
- **AND** 通常時は補助ボタンを隠して ◆ と選択中の名前を読め、フォーカスとポインターが離れれば元へ戻す。
- **AND** 行高と他の表示期間の操作を維持する。

### Requirement: REQ-017 - ヘッダーと必要ペースグラフ

WHILE ボードを表示するとき、GlitchBoardは SHALL 実績ペース、直近10稼働日の完了ポイントの棒、期間負荷、危険件数と、日別必要ペースの階段状SVGを表示する。\
グラフの数値ラベルは最大値の日だけに置き、必要ペースを青い面と階段状の線、実績ペースを黄色の破線、超過部分を赤い面と線で示す。\
学習中は実績値、負荷値、実績線、赤塗りを隠す。
ヘッダーではタイトル、期間切り替え、3つの指標を1行に置き、棒グラフは実績値の横へ置く。\
棒の高さは直近10稼働日の最大完了ポイントを基準に収め、0ptは薄い点で示す。\
必要ペースのSVGはタイムラインの最下段へ置き、日付列と揃える。\
最大値はpt付きの背景を持つラベルとして線の上に置き、線幅は画面幅によって変形させない。

#### Scenario: REQ-017-S01 - 学習中の表示

- **GIVEN** 最初の完了から5稼働日目である。
- **WHEN** ボードを開く。
- **THEN** 学習中と必要ペースを示し実績値と負荷値と赤塗りは示さない。

#### Scenario: REQ-017-S02 - 負荷の超過

- **GIVEN** 実績ペース2pt/日で必要ペースが3ptの日がある。
- **WHEN** グラフを描く。
- **THEN** 2ptまでの必要ペースを青く、超える部分だけを赤く塗り、その日の列も薄い赤になる。

### Requirement: REQ-018 - Event詳細エリア

WHEN Eventを選択したとき、GlitchBoardは SHALL Event要約、Story一覧、Task一覧を3列で表示し、未完了の直接 Task があれば直接 Task を、なければ未完了 Task を持つ最初の Story を初期選択する。\
ボードを開いたときは期限が近い順で最初の危険な未完了Eventを選び、なければ期限が最も近いEventを選ぶ。\
Story がない Event は「EventのTask」を選び、Story 作成なしで Task を追加できる案内を表示する。\
Event要約には残り暦日または超過日数、算出可能な完了予測日、残りptと未見積件数、済pt/全ptを示す。\
Storyには完了Task数とpt進捗バー、Taskには完了チェックとポイントバッジを示す。\
残り日数が負なら「n日超過」とし、学習中または実績0pt/日の完了予測日は表示しない。
期限接近、期限切れ、溢れのいずれかに当てはまるEventでは残り日数と期限超過の完了予測だけを赤で示す。

#### Scenario: REQ-018-S01 - 未完了Taskを選ぶ

- **GIVEN** 最初のStoryは完了済み、次のStoryに未完了Taskがある。
- **WHEN** Eventを選ぶ。
- **THEN** 次のStoryが選択され要約とTask一覧が表示される。

#### Scenario: REQ-018-S02 - 未完了Taskがない

- **GIVEN** Eventの全Taskが完了している。
- **WHEN** Eventを選ぶ。
- **THEN** 直接 Task があれば直接 Task を選び、なければ先頭 Story を選ぶ。
- **AND** 両方なければ直接 Task の追加を案内する。

#### Scenario: REQ-018-S04 - 初期選択

- **GIVEN** 期限切れの未完了Eventと、より後の期限を持つEventがある。
- **WHEN** ボードを開く。
- **THEN** 期限切れのEventを選択して詳細を表示する。

#### Scenario: REQ-018-S03 - 危険なEventの要約

- **GIVEN** Eventの完了予測日が期限より後である。
- **WHEN** Event詳細を表示する。
- **THEN** 残り日数と期限超過の完了予測を赤で示し、タイトルと他の数値は通常色に保つ。

### Requirement: REQ-030 - Event詳細の視覚表現

WHILE Event詳細を表示するとき、GlitchBoardは SHALL 要約、Story、Taskを枠で分け、各列を独立してスクロール可能にする。\
要約の済pt/全ptの下にProject色の進捗バーを示し、完了予測を月日と曜日で示す。期限内なら予測を緑で示す。\
選択中Storyの行全体を選択色にし、Story進捗バーを名前と件数の下に置く。\
Taskはチェック、名前、色付きポイント、操作ボタンの順に1行で示す。

#### Scenario: REQ-030-S01 - 期限内予測と進捗

- **GIVEN** Eventの期限が11月20日で、予測が11月16日、済13pt/全34ptである。
- **WHEN** Event詳細を表示する。
- **THEN** 「11/16(月)」の緑の予測とProject色の進捗バーを示す。

#### Scenario: REQ-030-S02 - Storyの選択色

- **GIVEN** Storyが選択されている。
- **WHEN** Story一覧を表示する。
- **THEN** 操作ボタンの位置まで行全体を選択色にし、進捗バーを名前の下に置く。

### Requirement: NREQ-004 - ボードの色と密度

WHILE ボードを表示するとき、GlitchBoardは SHALL 重なりの日を極薄い赤、今日を極薄い青、土日と祝日を少し明るい背景で区別する。\
今日の見出しは青字、休日の見出しは灰色とし、各行に今日を示す枠線を付けない。\
追加の「+」は枠線だけの控えめなボタンにする。ヘッダーのタイトル横へ今日の日付と曜日を小さく示し、必要ペースグラフの高さを抑える。

#### Scenario: NREQ-004-S01 - 祝日の今日

- **GIVEN** 今日が2026-11-03の祝日である。
- **WHEN** ボードを表示する。
- **THEN** 薄い今日の背景と青字の日付を示し、上枠線は付けない。

### Requirement: NREQ-003 - テーマ追従

WHILE VS Codeのテーマが変わるとき、GlitchBoardは SHALL ダーク・ライトの両方で文字、Project色、ポイント色、危険色を判読可能に表示する。

#### Scenario: NREQ-003-S01 - ライトテーマ

- **GIVEN** VS Codeのライトテーマを使用している。
- **WHEN** ボードを開く。
- **THEN** VS Codeテーマ変数を使った背景と文字になり危険の赤と21ptの赤紫を区別できる。


### Requirement: REQ-031 - ボードの上下高さ調整

WHEN タイムラインと詳細エリアの境界をドラッグしたとき、GlitchBoardは SHALL 上下の高さを連続して変更する。\
初期比率は境界を除いた上部と下部で3対2とする。\
各領域は原則80px以上とし、領域全体が小さい場合は境界を除いた高さの40%を下限とする。\
上下キーでも比率を変更でき、境界のダブルクリックまたはHomeキーで初期比率に戻す。\
件数が多い場合は領域内をスクロール可能にし、画面サイズ変更時は、下限に抵触しない範囲で選択した比率を維持する。

#### Scenario: REQ-031-S01 - 初期比率

- **GIVEN** ボードを新規表示し、境界を除いた領域の高さが780pxである。
- **WHEN** タイムラインと詳細エリアを描画する。
- **THEN** 上部は468px、下部は312pxになる。

#### Scenario: REQ-031-S02 - ドラッグによる高さ変更

- **GIVEN** 上部468px、下部312pxで選択Eventの詳細が表示されている。
- **WHEN** 境界を120px下へドラッグして離す。
- **THEN** 上部は588px、下部は192pxになり、Eventの選択を維持する。
- **AND** ポインターを離した後の移動では高さが変化しない。

#### Scenario: REQ-031-S03 - 領域の最小高さ

- **GIVEN** 境界12pxを含む領域の高さが532pxである。
- **WHEN** 境界を上端または下端を超える位置へドラッグする。
- **THEN** 上部と下部の高さはそれぞれ80px以上を維持する。

#### Scenario: REQ-031-S04 - キーボード操作と初期化

- **GIVEN** 上下の比率を変更し、境界にフォーカスがある。
- **WHEN** 上キー、下キー、Homeキーを順に押す。
- **THEN** 上部の比率が5ポイントずつ減少、増加し、最後に60%へ戻る。
- **AND** 境界のダブルクリックでも3対2へ戻せる。

#### Scenario: REQ-031-S05 - 多数Projectと画面サイズ変更

- **GIVEN** 23件のProjectがあり、上下の比率が3対2である。
- **WHEN** 画面を1440px×900pxから1100px×640pxへ縮小する。
- **THEN** 上下の比率を維持し、一覧をタイムライン領域内でスクロールできる。
- **AND** 詳細エリアの3列の独立スクロールを維持する。

#### Scenario: REQ-031-S06 - 下限調整後の画面縮小

- **GIVEN** 上下の片方を最小高さまで調整した。
- **WHEN** 境界を除いた高さが520pxになるまで画面を縮小する。
- **THEN** 両領域は80px以上を維持する。

### Requirement: REQ-032 - Projectの表示順変更

WHEN Project左端のハンドルを別のProject行へドラッグしたとき、GlitchBoardは SHALL 行の上半分なら直前、下半分なら直後へ移動する。\
上下キーでも隣の行へ移動できる。\
表示順は`manage.yaml`の`projects`配列へ保存し、再読込後も維持する。\
非表示Projectの位置、Projectファイル、設定とコメントを保持する。\
取消、外部のドロップ、同じ行への移動は変更せず、不正または消失した対象は拒否する。\
保存失敗は理由を表示し、表示順を確定せず再操作できるようにする。

#### Scenario: REQ-032-S01 - 行の前へ移動

- **GIVEN** A、B、Cの順でProjectが表示されている。
- **WHEN** AのハンドルをC行の上半分へドロップする。
- **THEN** B、A、Cの順になる。
- **AND** 移動先を示す線は操作終了後に消える。

#### Scenario: REQ-032-S02 - 行の後へ移動

- **GIVEN** A、B、Cの順でProjectが表示され、Eventが選択されている。
- **WHEN** AのハンドルをC行の下半分へドロップする。
- **THEN** B、C、Aの順になる。
- **AND** Eventの選択は変わらない。

#### Scenario: REQ-032-S03 - 順序の保存とデータ保全

- **GIVEN** 管理ファイルにA、非表示のH、B、Cが並び、コメントと設定がある。
- **WHEN** AをCの直後へ移動してからボードを読み直す。
- **THEN** 管理ファイルはB、H、C、Aの順となり、表示はB、C、Aになる。
- **AND** 設定、コメント、各`load`値とProjectファイルの内容は変わらない。

#### Scenario: REQ-032-S04 - 取消と無効な対象

- **GIVEN** Projectの移動中、または外部データがドラッグされている。
- **WHEN** 取り消す、外部データを落とす、同じ行へ落とす、または消失・非表示・不正な対象への操作を受信する。
- **THEN** 表示順と管理ファイルを変更しない。
- **AND** 受信した操作が無効ならエラーを返す。

#### Scenario: REQ-032-S05 - 保存失敗後の再操作

- **GIVEN** 管理ファイルへ書き込めず、ProjectはA、B、Cの順である。
- **WHEN** AをBの直後へ移動する。
- **THEN** 保存に失敗した理由を表示し、表示順はA、B、Cのままとする。
- **AND** 書き込める状態に戻せば同じ操作を再実行できる。

#### Scenario: REQ-032-S06 - キーボードによる移動

- **GIVEN** A、B、Cの順で、Bのハンドルにフォーカスがある。
- **WHEN** 上キーを押す。
- **THEN** B、A、Cの順で保存される。
- **AND** 下キーなら次のProjectの直後へ移動し、先頭の上キーと末尾の下キーでは変更しない。

### Requirement: REQ-037 - Event 追加の入口と空状態
WHERE 読み込み済みの Project がある場合、GlitchBoard はEVENT 一覧から Event を追加できなければならない(SHALL)。\
ボード上部には Event 追加を表示せず、選択中 Event の Project を追加先の初期値とし、選択がなければ最初の Project とする。\
保存後は作成した Event を選択する。\
WHEN データが空のとき、GlitchBoard は Project と Event のどちらを追加すればよいかを案内しなければならない(SHALL)。

#### Scenario: REQ-037-S01 - ボードから追加

- **GIVEN** 2番目の Project の Event を選んでいる。
- **WHEN** EVENT 一覧の Event 追加を開く。
- **THEN** 2番目の Project が初期選択され、名前と有効な期限の保存によりその Project に追加し、作成した Event を選択する。

#### Scenario: REQ-037-S02 - 空状態

- **GIVEN** ボードに表示する Event がない。
- **WHEN** ボードを表示する。
- **THEN** Project がなければ Project 追加を、Project があれば左の EVENT 一覧からの Event 追加を案内する。

### Requirement: REQ-040 - タイムライン寸法の調整
WHEN Project 列幅または行高を調整したとき、GlitchBoard は全 Project に共通の寸法を適用し、設定した最小値と最大値および表示面の幅に収めなければならない(SHALL)。\
ポインターとキーボードで調整、初期化でき、操作取消では元の値へ戻し、再表示でも確定値を維持しなければならない。

#### Scenario: REQ-040-S01 - 寸法の変更と再表示

- **GIVEN** Project が複数ある。
- **WHEN** 列幅と行高を変更して画面を再表示する。
- **THEN** 全行で確定値が維持され、上部の Event 追加は存在しない。

#### Scenario: REQ-040-S02 - 境界と取消

- **GIVEN** 寸法の調整操作が使える。
- **WHEN** 上限外へ調整し、次の操作を取り消す。
- **THEN** 最小最大を超えず、取消では操作前へ戻り、画面縮小後も日付と Project の操作に到達できる。

### Requirement: REQ-043 - 空状態の操作案内

WHILE 設定済みの画面が空である間、GlitchBoard は SHALL 管理データと読み込み、抽出の状態に応じて次の操作を案内する。\
Project 未登録ではメインの Project 追加、全 Project 非読込では左の抽出条件からの読み込み、読込済みで Event がない場合は左の Event 追加を案内する。\
抽出条件によって Event が見えない場合は抽出条件の確認を案内し、データがない状態と混同しない。\
未設定と管理ファイル不在の設定案内は既存の左だけの操作を維持する。

#### Scenario: REQ-043-S01 - Project 未登録

- **GIVEN** 有効な管理ファイルに Project が登録されていない。
- **WHEN** 左右の画面を開く。
- **THEN** 両方に Project 追加の案内を表示し、メインの Project ＋ が追加の入口であることを示す。

#### Scenario: REQ-043-S02 - 全 Project 非読込

- **GIVEN** Project が登録されているが、すべて load=false である。
- **WHEN** 左右の画面を開く。
- **THEN** 両方に読み込み設定の案内を表示し、左の抽出条件から Project を読み込むよう示す。
- **AND** Project が未登録であるという案内は表示しない。

#### Scenario: REQ-043-S03 - Event なし

- **GIVEN** 読込済みの Project に Event がない。
- **WHEN** 左右の画面を開く。
- **THEN** メインでは Event 追加、左では表示対象の Event がないことと追加の入口を案内する。

#### Scenario: REQ-043-S04 - 抽出結果なし

- **GIVEN** 読込済みの Project に完了済みの Event だけがあり、抽出条件は未完了 + 今後である。
- **WHEN** EVENT 一覧を開く。
- **THEN** 表示対象の Event がないことと抽出条件の確認を案内し、Project の追加や読み込みが必要だという案内を表示しない。
