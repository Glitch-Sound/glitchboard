# Spec Delta

## MODIFIED Requirements

### Requirement: REQ-022 - インライン追加

WHEN 各階層の見出しで追加を選んだとき、GlitchBoardは SHALL その場に入力欄を開き、Enterで必要項目を検証して保存し、Escで取り消す。\
Projectは名前と色、Eventは名前、Project、期限、StoryとTaskは名前を入力する。\
EventのProjectは選択中EventのProjectを初期値とし、Taskは未見積で作る。
追加の入力欄は保存が成功してから閉じ、失敗時は入力値を残す。
追加ボタンはProject、Event、Story、Taskそれぞれの見出しの右端へ置く。\
Projectの色は現在使用していない色を初期選択する。
追加ボタンは塗りつぶさず枠線で示し、EVENT一覧のEvent入力欄は見出し直下へ差し込み、名前欄に「Event名」を示す。
Eventの期限選択を操作したときは、Webview内にカレンダーを表示し、選んだ暦日を追加欄へ反映する。\
`showPicker()`が存在しない場合や例外となる環境でも、同じ操作で日付を選べる。\
この振る舞いは追加部品の`embedded`と`popover`の両レイアウトへ適用する。\
カレンダーは前月・翌月へ移動でき、選択だけでは追加を確定しない。\
カレンダーが開いている間のEscはカレンダーだけを閉じ、名前、Project、期限を保持する。\
期限の直接入力も受け付け、未入力または実在しない日付では保存要求を送信しない。

#### Scenario: REQ-022-S01 - Event追加

- **GIVEN** Event見出しで選択中Projectがある。
- **WHEN** 名前と期限を入力してEnterを押す。
- **THEN** そのProjectにEventが追加される。

#### Scenario: REQ-022-S02 - 取消

- **GIVEN** Storyの入力欄が開いている。
- **WHEN** Escを押す。
- **THEN** Storyは追加されず入力欄が閉じる。

#### Scenario: REQ-022-S03 - 保存失敗

- **GIVEN** 追加の入力欄に名前を入力した。
- **WHEN** 保存に失敗する。
- **THEN** 入力欄を開いたまま入力値を残し、画面上部に失敗理由を表示する。

#### Scenario: REQ-022-S04 - Project色の初期値

- **GIVEN** 既存Projectが青、紫、緑を使用している。
- **WHEN** Projectの追加欄を開く。
- **THEN** 既存Projectが使用していない色が初期選択される。

#### Scenario: REQ-022-S05 - DatePickerからEventを追加

- **GIVEN** 名前とProjectを指定したEvent追加欄が開き、`showPicker()`が存在しないか`SecurityError`を投げる環境である。
- **WHEN** 「期限を選ぶ」を押す。
- **THEN** Webview内に「期限のカレンダー」を表示し、日付を選べる。
- **AND** 日付を選ぶと期限へ反映し、カレンダーを閉じる。
- **AND** 日付を選んだだけでは追加要求を送らず、その後の追加確定で選んだ`YYYY-MM-DD`と名前とProjectを保存する。
- **AND** `embedded`と`popover`のどちらでも同じ結果となる。

#### Scenario: REQ-022-S06 - カレンダーの操作と取消

- **GIVEN** 名前、Project、期限を入力済みのEvent追加欄からカレンダーを開いている。
- **WHEN** Escを押すかカレンダーの枠外をクリックする。
- **THEN** カレンダーだけが閉じ、追加欄と各入力値を維持する。
- **AND** Escで閉じた場合は期限の選択操作へフォーカスが戻る。
- **AND** 期限ボタンはTabで移動してEnterまたはSpaceで開け、日付は矢印で移動してEnterまたはSpaceで選べる。
- **AND** カレンダーの操作キーだけではEventを追加しない。

#### Scenario: REQ-022-S07 - 期限の未入力と不正日付

- **GIVEN** Event名とProjectは入力済みで、期限は未入力、または直接入力した`2026-02-30`である。
- **WHEN** 追加を確定しようとする。
- **THEN** 保存要求を送らず、追加欄と名前とProjectを保持する。
- **AND** 未入力の場合はカレンダーを開いて期限の選択を案内する。
- **AND** 不正日付の場合は期限欄に理由を示し、直接修正またはカレンダーでの選択により追加を再操作できる。

#### Scenario: REQ-022-S08 - 月移動と暦日の保持

- **GIVEN** 選択済みの期限がある場合はその月、未入力の場合は日本時間の当月をカレンダーで表示する。
- **WHEN** 前月・翌月の操作で目的の月へ移動して日付を選ぶ。
- **THEN** `2026-12-31`から翌月の`2027-01-01`を選べ、`2028-02-29`も選べる。
- **AND** 保存要求の日付は選んだ暦日と一致し、端末のタイムゾーンによって前日または翌日へ変わらない。
- **AND** 過去日、休日、日本の祝日も選択できる。
- **AND** 有効な日付を`YYYY-MM-DD`で直接入力した場合も同じ日付を保存できる。

#### Scenario: REQ-022-S09 - 両テーマと狭い表示面

- **GIVEN** ダークまたはライトテーマで、幅240pxのEVENT一覧、または通常レイアウトのEvent追加欄を表示している。
- **WHEN** 期限のカレンダーを開く。
- **THEN** 月、曜日、日付、選択中の日付、フォーカスを判別できる。
- **AND** スクロール領域やフォームの枠で切れず、月移動と日付選択を操作できる。
- **AND** カレンダー表示によって画面外へ操作対象がはみ出さない。
