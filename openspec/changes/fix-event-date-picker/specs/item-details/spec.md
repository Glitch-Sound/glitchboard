# Spec Delta

## MODIFIED Requirements

### Requirement: REQ-027 - 詳細編集

WHEN 詳細パネルで編集を保存したとき、GlitchBoardは SHALL 名前、Event期限、Project色、Taskポイントを種類に応じて検証し、YAMLに保存して各表示と計算へ反映する。
Eventの期限欄では、追加欄と共通のWebview内カレンダーで日付を選べ、`YYYY-MM-DD`の直接入力も受け付ける。\
`showPicker()`が存在しない場合や例外となる環境でも期限を選べ、未入力または実在しない日付の保存要求は送信しない。\
日付の選択だけでは保存せず、保存を確定したときに選んだ暦日を反映する。\
カレンダーが開いている間のEscや枠外クリックはカレンダーだけを閉じ、詳細パネルと編集内容を保持する。

#### Scenario: REQ-027-S01 - 期限変更

- **GIVEN** Eventの期限が2026-11-10である。
- **WHEN** パネルで2026-11-12へ変更する。
- **THEN** タイムラインの◆と危険判定が更新される。

#### Scenario: REQ-027-S02 - Project色変更

- **GIVEN** 青いProjectがある。
- **WHEN** パネルで緑を選ぶ。
- **THEN** Project色が保存されマーカーも緑になる。

#### Scenario: REQ-027-S03 - 期限編集への横展開

- **GIVEN** Eventの詳細編集で期限が`2026-11-10`であり、`showPicker()`が存在しないか`SecurityError`を投げる環境である。
- **WHEN** 期限の選択操作を開く。
- **THEN** 共通のカレンダーに2026年11月と選択中の10日を表示する。
- **AND** 12日を選ぶと編集欄の期限は`2026-11-12`となり、保存操作までは保存要求を送信しない。
- **AND** 保存を確定すると同じ日付でYAML、タイムライン、危険判定を更新する。
- **AND** 直接入力、月移動、キーボード操作、両テーマでの表示も追加欄と同じ振る舞いとなる。
- **AND** 未入力または実在しない日付では理由を示し、保存要求を送らない。

#### Scenario: REQ-027-S04 - 期限編集のカレンダーだけを閉じる

- **GIVEN** 詳細パネルの編集中に名前と期限を変更し、カレンダーを開いている。
- **WHEN** Escを押すかカレンダーの枠外をクリックする。
- **THEN** カレンダーだけを閉じ、詳細パネルと編集中の名前と期限を保持する。
- **AND** Escで閉じた場合は期限の選択操作へフォーカスが戻る。
- **AND** 保存要求を送信せず、期限の選び直しや編集の継続ができる。
