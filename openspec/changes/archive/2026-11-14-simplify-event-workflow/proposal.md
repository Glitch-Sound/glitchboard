# 提案

## 目的

個人で Event に小さな作業を登録するとき、Story の作成と選択が先に必要となる。\
Event から直接 Task を追加し、目的の詳細を名前から開ける一貫した操作に変え、日常の登録と編集の手間を減らす。

## 変更内容

- Event の Task を Story 作成なしで追加し、必要なときだけ通常の Story で整理する。
- 既存 YAML、ID、通常 Story、ポイント、完了日、補足、既存の操作を維持する。
- Project、Event、Task の名前を詳細への入口にし、Story は選択と詳細ボタンを明確に分ける。
- ボードにも共通 Event 追加を置き、空の画面で次の操作を案内する。
- 同じ Event の更新では Story 選択と入力を維持し、取消、保存失敗、再操作を安定させる。
- 詳細編集は保存結果を待ち、失敗時に入力を維持し、取消後に現在値で再開する。
- 既存で判明していた画面縮小後の分割領域下限を修正する。

## 対象外

- 公開、push、Marketplace 登録、README への画像追加は依頼により行わない。
- 新しい同期サービス、データベース、分析式の変更は目的に必要ない。
- Task の Story 間移動は既存機能に存在せず、今回は追加しない。

## 対象の仕様

### 新規

なし。

### 変更

- `hierarchy-editing`: Event からの直接追加と更新中の選択、入力の維持。
- `item-details`: 名前からの詳細表示、編集の保存結果と取消。
- `board-visualization`: ボードの追加導線、空状態、領域下限。

## 影響

- 旧形式は無変換で読める。
  直接追加で作る保存用 Story に任意属性を足すが、旧版でも通常 Story と Task として読める。
- OpenSpec は指定テンプレートの ears-bdd と共通検査へ切り替える。
- 名前、補足、計算、削除確認は従来の通信と YAML 保存を通す。

## 未決事項

なし。
利用者から設計判断を委ねられたため、後から変更しやすい名称は「EventのTask」、通常 Story の説明は「必要なときだけ作業をまとめる」とする。
