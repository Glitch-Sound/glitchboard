# 差分仕様

## ADDED Requirements

### Requirement: REQ-035 - 名前から詳細を開く

WHEN Project、Event、Task の名前をクリックまたはキーボードで実行したとき、GlitchBoard は対象の詳細を直接開かなければならない(SHALL)。\
Story の名前は従来どおり Task 一覧の選択とし、共通の詳細ボタンを維持しなければならない(SHALL)。\
Task の完了チェックとポイント変更は詳細を開いてはならない。

#### Scenario: REQ-035-S01 - 名前と独立した操作

- **GIVEN** Project、Event、Task の名前が見えている。
- **WHEN** 下表の操作を行う。
- **THEN** 下表の結果となる。

| 操作 | 結果 |
| --- | --- |
| Project 名を実行 | Project 詳細 |
| Event 名を実行 | Event 詳細 |
| Task 名を実行 | Task 詳細 |
| Story 名を実行 | Task 一覧の選択 |
| Task 完了チェック | 詳細を開かず完了変更 |
| Task ポイント変更 | 詳細を開かずポイント変更 |

### Requirement: REQ-036 - 詳細編集の確実な保存と取消

WHEN 名前、期限、補足の編集を保存したとき、GlitchBoard は保存の結果を待ち、成功した場合だけ編集を閉じ、失敗時は入力を保持しなければならない(SHALL)。\
取消後は再開時点の保存済み値を表示しなければならない。\
Esc は最前面のカレンダー、削除確認、編集、詳細の順に現在の操作だけを取り消し、詳細を閉じた後は元の操作にフォーカスを戻さなければならない。

#### Scenario: REQ-036-S01 - 保存失敗からの再操作

- **GIVEN** 名前または補足を編集している。
- **WHEN** 保存が失敗して再度保存する。
- **THEN** 失敗時は入力を残し、成功した後に編集を閉じる。

#### Scenario: REQ-036-S02 - 取消と再開

- **GIVEN** 保存済みの名前または補足を変更し、取消した。
- **WHEN** 編集を再び開く。
- **THEN** 未保存の変更を含まず、現在保存されている値を表示する。

#### Scenario: REQ-036-S03 - Esc とフォーカス

- **GIVEN** 名前から詳細を開き、編集または削除確認が開いている。
- **WHEN** Esc を順に押す。
- **THEN** 最前面の操作だけが閉じ、詳細を閉じた後は元の名前にフォーカスが戻る。
