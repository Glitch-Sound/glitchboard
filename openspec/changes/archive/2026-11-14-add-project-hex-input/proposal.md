# 提案

## 目的

利用者が Project の設定色を正確なコードで指定できず、同じ色を再現しづらい。\
既存の色ピッカーに16進数入力を加え、追加と詳細で同じ指定と検証を使う。

## 変更内容

- Project の追加と詳細に #RRGGBB の直接入力を加え、ピッカーと同期する。
- 大文字、小文字と前後空白を受け付け、保存値を小文字の6桁へ正規化する。
- 無効な入力を送信せず、詳細の保存、取消、移動確認、保存失敗でも入力を保護する。

## 対象外

- 短縮色、透過色、色名と YAML 形式の拡張は、現在の保存形式と合わせるため扱わない。
- 画面全体のレビューは、この機能の検証後に別途行い、別の振る舞いをここへ混ぜない。
- push、公開、README の画面キャプチャ追加は行わない。

## 対象の仕様

### 新規

なし

### 変更

- `hierarchy-editing`: Project 色の直接入力と入力保護を定義する。

## 影響

- 共通の色入力、追加と詳細のフォーム、入力検証、テストと確認手順に影響する。
- 保存済みの有効な色、コメントと ID は変更しない。

## 未決事項

なし
