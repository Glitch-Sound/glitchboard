# Proposal

## Why

設定された`manage.yaml`が移動または削除されると、現在はエラーだけが表示され、利用者が画面から接続先を直せない。
未設定時には選択と作成のHTMLボタンがあるが、専用の装飾がなく、操作できるボタンとして見分けにくい。
管理ファイルがない状態から、作成または選択によって利用を始められる必要がある。

## What Changes

- 未設定時に加え、設定先の`manage.yaml`が存在しない場合も、ボードとEVENT一覧に作成・選択の案内を出す。
- 「新しく作る」「manage.yamlを選ぶ」を、背景、枠、余白、ホバー、キーボードフォーカスのあるボタンで表現する。
- 不在の場合は設定先のパスと理由を示し、利用者がボタンを押して保存先または既存ファイルを選べるようにする。
- 既存の作成・選択、取消、排他的な新規保存、設定変更後の同期を維持する。

## Scope

**In scope:**

- 起動時、設定変更時、ファイル監視による削除検知時の管理ファイル不在。
- 共通の案内UI、両表示面への状態通知、ダーク・ライトテーマでのボタンの視認性と操作性。
- 選択・作成後の復帰、取消と失敗時の再操作、既存読込エラーとの区別。

**Out of scope:**

- Project YAMLの欠落、YAML構文不正、権限エラーを管理ファイル不在として扱う変更。
  既存のデータ保全とエラー表示を維持する。
- ファイルの自動作成、管理データの移行、Git操作。
  作成は利用者の明示操作に従う。
- 稼働日、祝日、学習中、負荷配分、期限の計算変更。
  接続の復旧に関係しないため対象外である。

## Impact

- 実装と配置：Extensionの読込状態、共有メッセージ、Webviewの`ManageSetup`と両入口、案内用CSSが対象である。
- 互換性とデータ：YAML形式、既存設定キー、初期データ、設定の保存範囲を維持する。
  不在判定だけで設定やファイルを書き換えない。
- 依存関係と文書：追加パッケージは不要である。
  実装時にルートと拡張配布用のREADME、台帳を更新する。
  仕様の機能分担と読み順は変わらないため`specs/README.md`の構成変更は不要である。
