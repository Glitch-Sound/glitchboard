# 提案

## 目的

個人が左右の画面でレコードを選ぶ際、名前と詳細の動作が階層ごとに異なり、編集を保持して別項目へ移れない。\
選択と詳細の操作を統一し、作業面の寸法と情報の見せ方を調整して、実機確認で判明した操作負担を減らす。

## 変更内容

- サイドバーの表示と同時にメインボードを開き、左の Event にも詳細ボタンを設ける。
- **BREAKING** 名前による直接詳細をレコード選択へ変更し、詳細ボタンと、開いた詳細の追従へ移行する。
- 編集中の切替と終了では保存、破棄、キャンセルを選べ、失敗時は入力を残す。
- Project 列幅と全行共通の高さを調整し、上部 Event 追加と期限切れ列を除く。
- Story 見出し、仮想グループ Taks、Project 名と色を使った詳細ヘッダー、共通のポイント操作へ統一する。

## 対象外

- Story の自動保存とデータ移行。現行の直接 Task を表す仮想グループの表示名だけを Taks とする。
- push、公開、README の画面キャプチャ追加。

## 対象の仕様

### 新規

なし。

### 変更

- `vscode-integration`: サイドバー表示時の起動と安全なナビゲーション。
- `board-visualization`: 寸法調整、期限切れ列と追加入口、選択。
- `hierarchy-editing`: 仮想グループの名称。
- `item-details`: レコード選択、詳細ヘッダー、編集保護とポイント。
- `event-navigation`: サイドバーの詳細。

## 影響

- 保存 UUID、YAML 構造とコメントを維持し、画面状態と通信を変更する。
- 既存テストの旧操作に関する期待値は、依頼された新しい振る舞いへ更新する。

## 未決事項

なし。\
調整可能な寸法は design.md の D-03 で確定し、利用者は操作で変更できる。
