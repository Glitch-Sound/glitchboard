# 提案

## 目的

未設定時に左右の画面へ同じ設定案内が出て混乱する。\
メニュー起動を管理ファイルの状態に応じて分岐し、案内の入口を左の EVENT 一覧へ集約する。

## 変更内容

- 管理ファイルの初回判定を待って、設定済みで不在でない場合だけメインを開く。
- 未設定と管理ファイル不在では EVENT 一覧だけに設定案内を出し、新しいメインを作らない。
- 選択と作成の成功後には両画面を表示し、再起動でも同じ設定を使う。
- 既に開いたメインは自動で閉じず、表示と下書きを保持する。操作ボタンのない接続状態とエラーだけを示す。
- 構文、権限、Project の欠落は管理ファイル不在と区別し、既存のエラーと保全を維持する。

## 対象外

- 管理ファイルの自動生成、既存パネルの強制終了、YAML と保存モデルの変更。
- push、公開、README の画面キャプチャ追加。

## 対象の仕様

### 新規

なし。

### 変更

- `vscode-integration`: 設定に応じた起動と設定案内の集約。

## 影響

- Extension の非同期な設定読込とビュー起動、Webview の設定案内、関連する旧両画面案内のテストを変更する。

## 未決事項

なし。\
明示的な開くコマンドでも未設定時は左の一覧へ案内する。\
既存メインの不在時の表示と下書きは保持し、復元は監視で反映する。\
外部から設定やファイルを変更しただけでは閉じているメインへフォーカスを移さず、メニュー操作と設定UIの成功時に開く。
